> 版本：0.1 规划草案  
> 日期：2026-07-16  
> 当前状态：整体流程作为规划依据已确认；各模块细节仍需逐一评审  
> 事实依据：erp-web-business-fact-model.md
> 2026-07-30 范围修订：资产采购与资产台账退出当前原型；采购跨模块流程只讨论库存物料。设备仅作为生产资源基础资料维护，本文后续资产采购分支为历史内容，不再执行。

## 1. 流程设计原则

- 流程图描述业务责任和事实变化，不描述当前代码怎么调用。
- 每次跨模块交接都必须有来源对象、承接对象、明细行、数量和责任角色。
- 单据主状态只表示单据自身生命周期，跨模块结果使用独立状态维度。
- 正常流程、部分完成、异常、撤销和反向处理必须分别说明。
- 同一个业务结果只由一个模块负责落账，其他模块只读取摘要。

## 3. 销售到收款

### 3.1 正常主流程

~~~mermaid
flowchart LR
    A["报价单"] -->|客户接受| B["销售订单"]
    B --> C["订单确认与库存试算"]
    C --> D{"可用库存是否满足"}
    D -->|全部满足| E["库存预留"]
    D -->|部分满足| F["部分预留 + 生产缺口"]
    D -->|完全不足| G["生产缺口"]
    F --> H["生产任务待确认"]
    G --> H
    E --> I["销售出库需求"]
    H --> J["生产完工入库"]
    J --> I
    I --> K["仓库销售出库"]
    K --> L["客户签收/交付确认"]
    L --> M["销售开票"]
    M --> N["应收账款"]
    N --> O["收款与核销"]
    O --> P["销售闭环"]
~~~

### 3.2 模块责任

| 节点 | 责任模块 | 产生的事实 |
| --- | --- | --- |
| 报价和订单确认 | 销售 | 客户、产品、数量、价格、交期、商务条款 |
| 库存试算和预留 | 库存服务/仓库事实 | 来源订单行、预留数量、可用余额 |
| 生产缺口 | 销售需求事实 | 来源订单行、未满足数量、需求日期 |
| 销售出库 | 仓库 | 出库单、批次/库位、实际出库数量和库存流水 |
| 签收 | 销售 | 实际签收数量、时间、异常 |
| 开票、应收、收款 | 财务 | 发票行承接、应收、收款和核销 |

### 3.3 必须支持的变体

- 一张订单多行分别由库存和生产承接；
- 一行需求被库存和生产共同承接；
- 一行需求分多次出库、签收、开票和收款；
- 订单变更后重算未执行部分，释放或调整预留；
- 客户取消、退货、换货、折让和退款通过反向单据处理；
- 销售页面只发起交付需求，不替仓库执行出库。

## 4. 采购到付款

### 4.1 物料采购主流程

~~~mermaid
flowchart LR
    A["采购需求<br/>手动/库存缺口/生产备料"] --> B["采购申请"]
    B --> C["审批与采购承接"]
    C --> D["询价/供应商选择"]
    D --> E["物料采购"]
    E --> F["到货登记"]
    F --> G{"是否需要质检"}
    G -->|免检| H["待入库"]
    G -->|需检| I["质检冻结"]
    I --> J["来料质检"]
    J -->|合格/让步放行| H
    J -->|不合格| K["隔离/退货/复检/报废"]
    H --> L["仓库正式入库"]
    L --> M["合格在库与可用库存"]
    E --> N["采购发票"]
    L --> O["应付确认条件"]
    N --> P["应付账款"]
    O --> P
    P --> Q["付款与核销"]
~~~

### 4.2 资产采购分支

资产采购不进入普通物料库存：

~~~mermaid
flowchart LR
    A["资产需求"] --> B["资产采购申请/预算确认"]
    B --> C["资产采购"]
    C --> D["到货与验收"]
    D --> E["生成资产档案"]
    C --> F["采购发票"]
    E --> G["应付账款"]
    F --> G
    G --> H["付款与核销"]
~~~

### 4.3 必须支持的变体

- 多张采购申请合并成一张采购单；
- 一张采购申请拆给多个供应商；
- 分批到货、欠收、合理超收和关闭剩余数量；
- 到货不直接增加可用库存；
- 质检按数量部分放行、隔离、复检或退货；
- 供应商退货要能关联原采购、原收货、原质检和库存移动；
- 采购页面跟踪入库与付款摘要，不替仓库和财务执行操作。

## 5. 库存收发存

### 5.1 库存状态关系

~~~mermaid
stateDiagram-v2
    [*] --> 在途: 采购或调拨发出
    在途 --> 到货待检: 到厂收货
    到货待检 --> 待入库: 质检合格/让步
    到货待检 --> 隔离: 质检不合格
    隔离 --> 待入库: 复检合格/让步批准
    隔离 --> 已退货: 供应商退货
    待入库 --> 合格在库: 仓库入库过账
    合格在库 --> 已预留: 销售/生产/电商占用
    已预留 --> 已分配: 指定出库/领料作业
    已分配 --> 已出库: 仓库过账
    已预留 --> 合格在库: 预留释放
    合格在库 --> 冻结: 盘点/质量/异常冻结
    冻结 --> 合格在库: 解冻
~~~

### 5.2 库存作业

| 作业 | 来源 | 关键校验 | 库存影响 |
| --- | --- | --- | --- |
| 采购收货 | 物料采购行 | 剩余可收数量、单位、批次要求 | 增加物理在厂和待检/待入库，不增加可用 |
| 采购入库 | 有效收货与放行凭证 | 待入库数量、仓库、库位、批次 | 增加合格在库，更新可用 |
| 销售出库 | 销售出库需求和预留 | 可出库数量、批次、库位 | 扣减在库并消耗预留 |
| 生产领料 | 工单释放和物料分配 | 分配数量、齐套、批次 | 扣减原料在库并消耗生产分配 |
| 生产退料 | 原领料记录 | 可退数量、质量状态、工单 | 增加对应状态库存 |
| 完工入库 | 生产放行数量 | 可入库额度、质检、批次 | 增加成品合格在库 |
| 调拨 | 调拨申请 | 调出可用、在途、调入确认 | 调出扣减、在途增加、调入过账 |
| 盘点 | 盘点计划和明细 | 冻结范围、账实差异、审批 | 产生盘盈/盘亏流水 |

### 5.3 统一口径

- 物理在库回答“货是否在厂/仓”；
- 合格在库回答“是否已通过质量并完成仓库过账”；
- 可用库存回答“现在还能被新需求占用多少”；
- 预留回答“已承诺给谁但尚未出库多少”；
- 分配回答“已进入具体作业但尚未过账多少”；
- 待检、待入库、在途和隔离只能作为补充信号。

## 7. 生产与质量

本阶段只固定跨模块边界，详细页面在前置模块完成后再设计。

~~~mermaid
flowchart LR
    A["销售缺口/备库需求"] --> B["生产任务"]
    B --> C["物料需求试算"]
    C --> D["备料申请"]
    D --> E["仓库受理/采购缺口"]
    B --> F["计划工单"]
    F --> G["工单释放"]
    G --> H["生产领料"]
    H --> I["流转批次与现场执行"]
    I --> J["报工与生产质检"]
    J -->|放行| K["包装与入库检验"]
    K --> L["完工入库"]
    J -->|不合格| M["返工/报废/让步/异常"]
    M --> J
~~~

固定边界：

- 缺料不阻止建立生产任务和计划工单，但限制释放、领料和开工；
- 生产页面不能直接判定质量合格或增加库存；
- 质检页面不能代替生产报工或仓库入库；
- 工单、释放批次和流转批次分别表示计划、获准执行和现场执行；
- 生产详细流程保持“待后续模块评审”，已有接口不自动冻结最终交互。

## 9. 异常与反向处理

| 场景 | 正确处理方式 | 不允许 |
| --- | --- | --- |
| 销售取消未执行数量 | 关闭剩余需求、释放预留、取消未执行承接 | 删除已发生的出库和发票 |
| 销售退货 | 售后单 → 收货 → 退货质检 → 重新入库/报废 → 退款或换货 | 直接把原销售订单改回草稿 |
| 采购退货 | 关联原采购/收货/质检的退货单和库存移动 | 直接减少采购订单已到货数量 |
| 库存差异 | 盘点差异单和盘盈/盘亏流水 | 直接改余额不留来源 |
| 发票错误 | 红字/冲销和重新开票 | 覆盖已确认发票 |
| 收付款错误 | 反向核销、退款或冲正 | 删除历史资金记录 |
| 生产不良 | 质量判定 → 返工/报废/让步/复检 | 直接把不良数量改成合格 |

## 10. 黄金演示流程

全系统原型至少共用以下场景：

1. 现货销售：订单 → 预留 → 出库 → 签收 → 开票 → 收款；
2. 缺货生产：订单 → 生产任务 → 补料采购 → 来料质检 → 生产 → 完工入库 → 出库；
3. 部分交付：库存承接一部分、生产承接一部分，并分批出库和结算；
4. 来料不合格：到货 → 部分合格 → 隔离 → 退货/复检；
5. 生产不良：报工 → 检验不合格 → 返工 → 复检 → 入库；
6. 资产采购：需求 → 采购 → 验收 → 资产档案 → 付款；
7. 电商履约：订单导入 → ERP 销售 → 出库 → 发货回传 → 售后/对账。

这些场景必须共享同一批客户、供应商、物料、订单、库存和金额事实。
