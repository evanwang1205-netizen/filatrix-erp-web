## 1. 模块目标

基础资料模块负责维护所有业务模块共同引用的稳定对象、默认值和使用状态。

它必须解决以下问题：

- 业务单据引用的是同一个客户、供应商、物料、单位、仓库和人员；
- 常用默认值可以自动带入单据，并允许在单据中按本次业务修改；
- 停用对象不能再用于新业务，但历史单据仍能完整查看；
- 主数据字段足以支撑销售、采购、仓库、财务和生产，不需要后续在业务页面临时补写；
- 资料维护和业务执行严格分开，不把主数据页做成流程单据。

## 2. 当前页面观察

2026-07-16 已在浏览器检查物料、客户、供应商和公司页面，发现：

1. 物料列表信息相对集中，但客户、供应商、公司列表在中等宽度下出现明显横向滚动，关键状态和维护入口容易被推到右侧；
2. 列表同时支持整行进入详情、行内编辑和更多操作，入口较重复；
3. 客户和供应商列表把联系方式、地址、默认业务信息全部铺开，列数过多；
4. 详情页大量使用只读输入框和禁用下拉，视觉上像“不可编辑的编辑页”；
5. 右侧摘要重复左侧已有字段，没有充分展示“当前是否可引用、被哪些业务使用、停用会影响什么”；
6. 公司当前只有一条资料，但仍使用普通分页列表并显示“新建”，不符合单公司原型的使用方式；
7. 物料已有分类、业务属性、单位、批次、效期和质检字段；交期、生产周期和补货参数按事实归属分别进入采购、生产与仓库设置；
8. 客户和供应商已有默认地址、物流/交付、付款、税率和开票资料，方向正确，但信息分组和详情呈现需要重排。

以上是现状判断，不代表直接照现有字段实现。

## 3. 对象边界

| 对象 | 定义 | 被谁引用 | 不包含 |
| --- | --- | --- | --- |
| 公司 | 当前经营主体的法定、联系、开票和银行资料 | 全系统 | 账号、部门人员、交易结果 |
| 部门 | 组织层级和业务归属单位 | 员工、供应商归属、资产、仓库、产线 | 权限角色、客户固定归属 |
| 员工 | 真实人员及任职信息 | 单据负责人、经办人、操作人 | 登录账号和权限 |
| 计量单位 | 全局业务单位及预留英文简称 | 物料、数量字段 | 单位换算、某个物料特有的包装关系 |
| 仓库 | 库存保管范围和库位规则 | 库存、收发存、物料默认值 | 当前库存余额 |
| 物料 | 可销售、采购、库存或生产引用的产品/原料/包材/半成品 | 销售、采购、仓库、生产、质检 | 配方、工艺和库存数量 |
| 客户 | 购买方身份、联系、收货和交易默认值 | 报价、订单、售后、发票 | 销售订单和应收结果 |
| 供应商 | 供货方身份、联系、交付和交易默认值 | 采购、退货、质检、采购发票 | 采购订单和应付结果 |
| 资产 | 非库存资产的档案和使用归属 | 资产采购、生产、维护 | 采购过程和费用结果 |
| 产线 | 生产资源及管理归属 | 工单、排产、工作台 | 工艺模板和现场执行记录 |

## 4. 使用状态规则

### 4.1 通用状态

基础资料统一使用：

- 启用：允许被新单据和新配置引用；
- 停用：禁止新增引用，历史引用保持可见。

“维护中”不是通用主数据状态。设备或产线临时维护属于生产资源可用性事实；仓库盘点冻结属于库存事实，不能混入通用使用状态。

### 4.2 停用规则

停用前必须显示影响：

- 是否存在未完成业务单据；
- 是否仍是其他资料的默认值；
- 是否存在库存余额、预留或在途数量；
- 是否被启用中的规则、配方、工艺或账号引用。

处理规则：

| 对象 | 可以直接停用的条件 | 有活动引用时 |
| --- | --- | --- |
| 客户/供应商 | 无新业务必须继续创建 | 允许停用，但未完成单据继续执行并明确提示 |
| 物料 | 无库存、预留、在途和活动需求 | 阻止停用，先处理库存和活动需求 |
| 仓库 | 无库存、冻结、在途和未完成作业 | 阻止停用 |
| 单位 | 未被启用物料或业务规则引用 | 阻止停用 |
| 部门 | 无在职员工和启用资源 | 阻止停用或要求迁移 |
| 员工 | 无待办责任必须转移 | 要求先转移待办，再停用 |
| 资产/产线 | 无活动生产或维护任务 | 阻止停用或要求结束任务 |

原型第一版至少要在停用确认框中显示影响摘要，不允许静默停用。

## 5. 通用页面模板

### 5.1 列表

统一结构：

1. 标题和对象特定的新建按钮；
2. 主搜索框；
3. 1–3 个对象特定筛选；
4. 4–6 个扫描列；
5. 固定在右侧的使用状态；
6. 分页。

交互规则：

- 整行点击进入详情；
- 不保留单独“维护”列和行内编辑图标；
- 启用/停用等低频动作进入详情页；
- 更新时间默认不占主列，放详情日志；只有确实用于资料治理时才作为筛选/排序项；
- 导出保留为次操作；
- 使用状态默认筛选为“启用 + 停用”，但停用对象视觉降级。

### 5.2 详情

~~~mermaid
flowchart TB
    A["标题区<br/>返回、名称、编码、使用状态、编辑"] --> B["对象判断<br/>是否可引用、关键规则、风险/缺失"]
    B --> C["主信息区<br/>按业务分组的只读文本和事实表"]
    C --> D["可选关系区<br/>仅展示用户需要理解或维护来源的真实业务关系"]
    D --> E["附件与日志"]
~~~

公司、部门和计量单位不展示引用数量摘要；引用投影仍可在保存命令中用于改名、停用等完整性保护。

详情页规则：

- 只读事实使用文本、描述列表和小表格，不使用 readonly 输入框；
- 右侧只显示使用状态、资料完整度、引用影响和风险，不重复主内容；
- 编辑是唯一主动作；
- 启用/停用、复制等低频动作进入更多菜单；
- 不显示流程节点和“下一步”；
- 空字段不占据大块空间，关键缺失项使用“待完善”提示。

### 5.3 新建/编辑

- 使用真实表单控件；
- 自动编码在新建页显示“保存后生成”或编码规则预览；
- 保存草稿不是主数据流程状态，页面只保存资料；
- 新建成功进入详情，编辑成功返回详情；
- 未保存离开需要确认；
- 返回列表、页面标题与保存/编辑进入公共顶部栏，长表单滚动时仍可操作；
- 客户、供应商、物料等复杂对象按分区表单；
- 轻量资料使用单栏或双栏紧凑表单。

## 6. 列表规格

### 6.1 物料

| 列 | 主值 | 摘要 |
| --- | --- | --- |
| 物料 | 名称 | 编码、图片/缩略标识 |
| 型号/规格 | 型号 | 规格 |
| 业务属性 | 分类 | 销售、采购、生产适用范围 |
| 单位/追溯 | 基础单位 | 批次、效期 |
| 质量要求 | 到货检验 | 完工检验、常用仓库 |
| 使用状态 | 启用/停用 | 缺失关键资料提示 |

筛选：分类、业务属性、质检要求、使用状态。  
默认排序：启用优先，其次名称/编码。

### 6.2 客户

| 列 | 主值 | 摘要 |
| --- | --- | --- |
| 客户 | 客户名称 | 编码、客户类型 |
| 联系方式 | 主要联系人 | 电话 |
| 公司地址 | 城市/地区 | 公司详细地址 |
| 商务默认值 | 付款方式 | 信用额度/账期 |
| 使用状态 | 启用/停用 | 资料缺失提示 |

客户负责人、归属部门、邮箱、默认收货、物流方式和完整开票资料不进入列表。默认收货保留在详情与编辑页，不能替代公司地址。

### 6.3 供应商

| 列 | 主值 | 摘要 |
| --- | --- | --- |
| 供应商 | 供应商名称 | 编码、供应商类型 |
| 联系方式 | 默认联系人 | 电话 |
| 公司地址 | 城市/地区 | 公司详细地址 |
| 采购默认值 | 交付方式 | 付款方式、税率 |
| 使用状态 | 启用/停用 | 新业务引用影响 |

固定采购员、归属部门、邮箱、注册地址和完整开票资料不进入列表。列表地址读取供应商公司经营地址，不读取财税注册地址。

### 6.4 仓库

| 列 | 主值 | 摘要 |
| --- | --- | --- |
| 仓库 | 名称 | 编码、仓库类型 |
| 所属公司 | 公司名称 | 仓库类型决定业务能力 |
| 位置 | 城市/地区 | 真实地址 |
| 库位 | 库位数量 | 库位编码规则 |
| 使用状态 | 启用/停用 | 库存/作业阻断提示 |

列表不显示库存余额；库存数量进入仓库模块。

### 6.5 轻量资料

| 页面 | 列 |
| --- | --- |
| 计量单位 | 单位、英文简称、使用状态 |
| 部门 | 部门名称/编码、所属公司/上级部门、启用员工、使用状态 |
| 员工 | 姓名/工号、部门/岗位、联系方式、使用状态 |
| 资产 | 名称/编号、品牌/型号、部门/位置、出厂编号、使用状态 |
| 产线 | 名称/编码、类型、车间/部门、标准产能、适用范围、使用状态 |

### 6.6 公司

当前采用“默认公司 + 轻量多公司”的口径：

- 公司使用普通列表、详情、新建和编辑路径；
- 当前默认经营主体为 `COM-FILATRIX`，但路由、资料和业务单据不硬编码唯一公司；
- 公司主档维护中文法定名称、英文名称、中文经营地址和英文地址；英文资料当前只作为可选主档信息保存，不被销售单据或 PDF 引用；
- 报价、销售订单、采购申请和采购订单可选择启用公司，下游单据继承来源公司；
- 暂不引入集团组织、跨公司结算、内部交易和合并报表。

公司停用只影响新的业务引用，历史单据继续保留原公司归属。

## 7. 详细字段设计

### 7.1 物料

#### A. 基本资料

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 物料编码 | 自动 | 按分类/编码规则生成，不允许用户随意覆盖 |
| 物料分类 | 是 | 成品、半成品、原料、包材、辅料、其他 |
| 物料名称 | 是 | 业务使用名称 |
| 型号 | 否 | 产品/材料型号 |
| 规格 | 是 | 可用于销售、采购和仓库识别 |
| 基础单位 | 是 | 销售、采购、生产、收发货、库存和价格的统一计量单位 |
| 英文名称 | 否 | 可选英文主档资料，当前没有业务单据或 PDF 消费者 |
| 英文型号 | 否 | 可选英文主档资料，可搜索和导出，当前不进入业务快照 |
| 英文规格 | 否 | 可选英文主档资料，当前没有业务单据或 PDF 消费者 |
| 图片 | 否 | 主图，详情可查看 |
| 使用状态 | 是 | 启用/停用 |

“成品”是物料分类，不是另一套对象。

#### B. 单位规则

所有业务数量和单价统一使用基础单位，不维护销售/采购单位或对应折合关系。`kg` 与 `g` 是可分别选择的业务单位，系统不自动换算；袋、箱、托等包装数量属于包装规格、包装规则或单据要求。

#### C. 业务属性

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 是否可销售 | 是 | 只控制销售选品 |
| 是否可采购 | 是 | 只控制采购选品，不等同于物料分类 |
| 是否可产出 | 是 | 控制能否作为配方和生产工单的产出物料 |

采购页面不能因为物料不是成品而排除候选。

三项业务属性相互独立：成品可以同时采购和生产，原料也可以销售；“采购+自制”不再压缩成一个承担多重含义的主字段。

采购交期、默认供应商、采购价和最小采购量属于“供应商—物料关系”；生产周期属于配方、工艺或生产计划参数，不在物料日常页面重复维护。

#### D. 库存与质量

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 常用仓库 | 否 | 新建业务的默认值，可按本单修改 |
| 批次追踪 | 是 | 按批次/不追踪 |
| 效期 | 是 | 无效期要求/适用 |
| 效期（月/天） | 条件必填 | 适用时填写 |
| 到货检验 | 可采购时必填 | 需质检/抽检/免检 |
| 完工检验 | 可产出时必填 | 需质检/抽检/免检 |

“质检”不能只保留一个模糊开关；到货检验和完工检验按业务属性条件显示。不适用与免检必须区分。

安全库存、补货点、最高库存和补货批量属于“仓库—物料补货设置”，因为同一物料在不同仓库可以采用不同参数。

### 7.2 客户

分区：

1. 基本信息：编码、名称、类型、使用状态；
2. 公司联系与地址：主要联系人、电话、邮箱、公司所在地区和详细地址；
3. 默认收货：收货人、收货电话、收货地址和物流方式，可扩展多地址；
4. 商务默认值：付款方式、币种、税率、信用额度、账期；
5. 开票资料：抬头、税号、注册地址、开票电话、开户行、银行账号；
6. 附件和备注。

客户主档不维护归属部门或固定客户负责人；销售责任保存在具体报价、订单和售后单据中。公司联系/地址与默认收货分别保存，只有用户显式执行“从公司信息带入”时才复制一次，之后互不覆盖。客户的默认值带入报价和销售订单后允许按本单修改。

### 7.3 供应商

分区：

1. 基本信息：编码、名称、类型、使用状态；
2. 公司联系与地址：主要联系人、电话、邮箱、公司所在地区和详细地址；
3. 可供物料：物料型供应商维护可供物料、供应商料号、起订量、供货周期和默认供应商关系；
4. 采购默认值：交付方式、付款方式、账期、币种、税率；具体采购提前期维护在物料—供应商关系；
5. 开票与收款资料：抬头、税号、注册地址、开票电话、开户行、银行账号；
6. 附件和备注。

供应商主档不维护归属部门或固定采购员；采购责任保存在具体采购单据。公司经营地址与注册地址分别保存，不互相回退。供应商“可供物料”是采购选择和建议依据，不直接替代采购价格记录。
供应商主档不维护手工供货范围、供应商级来料检验或简化资质状态。设备供应商和物流服务供应商不要求建立物料—供应商关系；其采购对象、服务范围和验收要求进入具体采购与验收单据。

### 7.4 仓库

分区：

1. 基本信息：编码、名称、类型、公司、使用状态；
2. 位置：厂区/地区、地址；
3. 库位：库位数量和编码前缀；
4. 仓库—物料补货关系；
5. 附件和备注。

仓库详情可显示“当前库存与未完成作业摘要”用于停用判断，但不能维护库存数量。
仓库主档不维护管理部门、固定负责人、联系电话、自由文本保管范围或手工用途开关；仓库类型由服务端派生业务能力，具体责任进入收货、出库、调拨、盘点与处置单据。

### 7.5 计量单位

字段：

- 单位；
- 英文简称；
- 使用状态；
- 使用说明。

“单位”是中文系统中物料选择和业务数量展示的唯一值。“英文简称”可保存 `kg`、`g`、`roll`、`pcs`、`ctn` 等辅助英文资料，当前不参与选择、计算、校验、单据展示或打印，也没有销售单据或 PDF 消费者。主档不维护符号、类型、基准单位、换算系数或小数精度，不同单位之间不自动换算。

已被物料引用的单位不能修改名称或停用；说明仍可维护。英文简称没有业务引用，因此允许修改。若未来出现明确消费者，应重新评审快照与引用保护，不能预设为当前打印方案的一部分。

### 7.6 公司、部门、员工

公司：

- 主体名称、简称、统一社会信用代码；
- 地址、电话、邮箱；
- 开票资料和银行账户；
- 公司印章/Logo 等附件；
- 使用状态。

部门：

- 编码、名称、所属公司、上级部门、使用状态和备注；
- “启用员工”由员工当前归属和使用状态实时统计，不在新建或编辑表单中维护，也不作为劳动关系在职人数；
- 不维护部门类型或固定负责人；员工主档同样不维护固定直属上级，业务责任进入具体单据、审批规则或执行事件；
- 不维护概括性的主要职责；部门详情不展示引用数量，但服务端引用保护继续生效；
- 必须阻止跨公司上级、自身上级和循环层级。

员工：

- 工号、姓名、部门、岗位；
- 电话、邮箱、性别、入职日期、使用状态和备注；
- 不维护用工类型、任职状态或固定直属上级；具体业务责任进入单据、审批规则或执行事件；
- 账号关联在岗位归属中只读显示，账号本身在系统模块维护。
- 页面按基本资料、岗位归属、联系信息和备注分组；性别与入职日期属于基本资料，联系信息只放手机和邮箱。

### 7.7 资产和产线

资产：

- 编号、名称、品牌/型号、规格、序列号；
- 使用部门、位置；
- 来源资产采购、启用日期、使用状态；
- 资产说明和附件；
- 不维护没有业务消费方的资产类型或固定负责人；
- 当前没有维护事件和提醒闭环，因此不保存静态运行状态或保养周期；未来由保养/维修事件投影。

产线：

- 编码、名称、类型、所属部门、车间/区域；
- 适用范围；
- 标准产能及单位；
- 使用状态和说明；
- 不维护固定负责人、静态运行状态或与车间/适用范围重复的摘要字段。

产线临时停机和维护不在主数据页处理；当前实际占用读取设备作业记录。未来若建立运行状态，必须由生产或维护事件投影，不在基础资料页手填。

### 14.12 关系来源与库存执行入口复查（2026-07-23）

- 物料详情的“可供供应商”明确读取供应商“可供物料”关系，并提供供应商维护入口；“仓库补货设置”明确读取仓库“物料补货设置”关系，并提供仓库维护入口。两段均为只读反向视图，无启用关系时隐藏整段。

## 15. 基础资料模块完成标准

- 所有页面职责明确，无流程节点和伪业务状态；
- 中等宽度下无需横向滚动即可判断对象身份和使用状态；
- 详情不使用只读输入框冒充文本；
- 新建/编辑字段、详情信息、搜索范围和导出字段保持可追溯的一致关系；
- 列表无重复维护入口；
- 物料能支撑销售、采购、仓库、质量和未来生产所需关键属性；

- 停用规则能解释引用影响；
- 简单资料和复杂资料分别使用合适模板；
- 空态、未找到、加载、错误、无权限和停用状态完整；
- 用户确认页面内容与布局后标记为“已冻结”。
