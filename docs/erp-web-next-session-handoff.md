## 2. 当前范围与稳定规则

- 当前迭代集中在基础资料、销售、采购、仓库、生产、质检、设备及系统支撑；电商暂不进入本轮。首页、报表等产品规划以蓝图为准。
- 独立财务、资产采购和资产台账已退出；销售开票/回款和采购收票/付款仅为轻量商务跟进，不生成会计凭证或资金核销。兼容历史数据不构成恢复模块的理由。
- 设备主档保存生产资源身份；独立设备模块包含巡检任务、计划、标准，完成任务本身就是巡检记录。
- 单据生命周期与库存、质量、交付、商务进度分开表达；跨单据承接必须落实到来源行与数量。实际操作人、责任快照、日志和打印快照不得为统一展示而重写。
- 数量使用物料基础单位，大盘半成品按 kg、复绕成品按卷；单位主档不承担自动换算。工单按配方计算需求并冻结生产标准，实际领退料和损耗独立记录。
- 仓库类型表达物理用途，职能决定流程准入；质量判定与库存可用状态来自执行事实。库存、预留、分配、冻结和冲销必须保持数量守恒。
- 已验收的 PDF/打印模板未经明确要求不改；现有测试数据未经明确要求不重置。

## 5. 启动与验证

项目目录始终是当前克隆的仓库根目录。新电脑先安装 Node.js 和 Git；本次迁移验证使用 Node.js 24.16.0、npm 11.13.0。执行 `npm ci` 按锁文件安装依赖。分别在两个终端运行：

```powershell
npm.cmd run api
```

```powershell
npm.cmd run dev:5174
```

前端 `http://127.0.0.1:5174`；API `http://127.0.0.1:5175/api`。保留已克隆的测试数据，启动 API 会按现有代码执行兼容迁移。角色导航依赖当前账号权限，出现 `accessDenied` 时先检查账号与角色。

常用静态和构建检查：

```powershell
npm.cmd run audit:ui
npm.cmd run smoke:frontend
node --check server/index.mjs
npm.cmd run build
```

业务变更按范围选择烟测，例如 `smoke:warehouse`、`smoke:sales-inventory`、`smoke:flow`。运行前阅读对应脚本，确认使用临时数据与临时端口。

**`smoke:api` 包含写入和数据文件修改，默认连接 5175 并读取主数据；不能当作只读检查直接运行。** 必须先为它准备隔离 API/数据，并同时设置匹配的 `FILATRIX_DATA_FILE` 和 `FILATRIX_SMOKE_API_BASE`。其他烟测也不得未经检查就假定安全。
