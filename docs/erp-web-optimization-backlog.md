## 历史生产模块推进记录（2026-07-11，已完成）

本轮从生产规则类页面开始收敛，物料配方已完成规则口径、用量模型和版本控制第一轮，工序节点和工艺模板已进入前端优化；后续继续按用户逐页反馈收敛。

- 全局字体口径调整为“兼容优先 + 中文观感优化”：优先使用 Inter、HarmonyOS Sans SC、MiSans、Alibaba PuHuiTi 3.0、思源/Noto CJK 等现代字体，再回退到 PingFang SC、Segoe UI、Microsoft YaHei UI 和系统字体；当前不引入在线字体依赖，后续如需跨设备完全一致，再评估内置 `woff2` 字体资源。
- 字体观感问题不只来自字体命中，也来自字重和只读控件层次。工序节点详情页曾试验“节点概览 + 系统规则说明块 + 触发/生成/完成流程卡”和单页专属只读样式，实际观感不稳定且和系统既有单据页割裂，已回退到统一单据页样式：保留“基本信息 + 动作配置”的业务结构，不再挂工序节点专属页面 wrapper 和独立 CSS 覆盖；后续要做高级感，应先统一全局表单密度、字号层级、只读态和右侧摘要。
- 物料配方已确认按规则/主数据维护页处理，不走业务流程单据；新建页不放流程节点和状态摘要，详情页右侧保留维护状态、规则摘要和附件。
- 配方不再要求手填配方名称；列表第一列显示配方编号，版本号在编号下方展示。
- 同一成品允许维护多个配方版本，但同一时间只能启用 1 个版本；新建配方选择成品后，版本号按该成品已有最大版本自动递增，版本号不手填。
- 配方基础字段保留适用成品、自动版本号、单位、每单位净重、启用状态和备注；单位来自物料属性，不手工选择。
- 新建配方页右侧只补“版本提示”，显示当前成品已有版本数量、当前自动生成版本、当前启用版本和唯一启用提示；不恢复完整维护状态/规则摘要。
- 配方明细支持两种用量：投料占比和固定用量。投料占比用于按成品重量计算 kg 用量；固定用量用于包材等按每单位成品固定领用的物料。
- 配方明细不再填写损耗。损耗改为独立“预估损耗”区，表达每次生产开机/任务层面的固定损耗和比例损耗；生产任务计算预估需求时，先按配方明细计算，再按任务额外叠加预估损耗。
- 配方明细和预估损耗均禁止重复物料；重复选择要在选择器和提交校验两层拦截。
- 物料引用选择器在所有模块不展示最近价，只展示业务判断所需的物料识别信息。
- 工序节点进入第一版前端重构：工序节点不是现场流转记录，也不是生产任务本身；它是工艺模板、生产工单和质检节点可引用的系统预设动作库。节点名称、编号和动作配置固定，用户不可新增、复制、编辑或停用；列表按“工序节点 / 触发动作 / 完成条件 / 异常规则”展示，不再显示更新列和独立维护状态列，且去掉“系统预设”、重复触发时机和异常闭环等说明，避免能力清单看起来像可维护业务单据。
- 工序动作限定为系统预设项，例如仓库发料、确认领料并烘干、开机确认、开机检、半成品报工、半成品报工检、成品报工、包装确认、入库检、完工入库。动作的执行方、触发时机、生成内容、完成事件、是否阻断下一工序和异常事件由系统维护，作业资料放到工艺模板中填写。
- 工艺模板的工序编排开始承接现场作业资料：每道工序在选择系统工序节点后，可维护核心设备、作业内容、控制点和常见问题；这些内容属于当前工艺模板，不再放在系统工序节点里维护。
- 工艺模板工序编排不再使用挤压式明细表承载作业资料，改为连续工艺卡行：序号只作为左上角角标，不单独占列；每道工序顶部使用“节点头”展示工序节点和系统动作，节点名、编号和动作摘要保持同层级对齐；下方再用统一标签行维护核心设备、作业内容、控制点、常见问题，确保新建和详情页读写口径一致。
- 生产任务确认定位为“生产需求/计划待办”，字段源头以生产工作台第一个页签“任务建单”的待办任务详情为准；一个生产任务可以承载一个来源单据下的多项成品需求，不应被设计成单一成品的“建议生产”表。
- 生产任务列表调整为“生产任务 / 来源 / 成品需求 / 工单/进度 / 物料备料”；详情/新建页按“任务基础 / 成品明细 / 预估物料与备料 / 关联工单”组织，核心字段为来源单据、负责人、优先级、创建时间、交期、计划生产、入库进度、成品需求数量、已建工单、已入库、待建工单和物料备料状态。
- 生产任务来源单据不可手填：销售订单缺口生成的任务自动带入销售订单号、内部发货日期和销售订单负责人；手动新建任务没有来源单据。优先级只保留正常、加急；建单状态由流程和数据计算，只在列表、右侧摘要和工作台作为系统判断展示，不进入新建/编辑表单。
- 生产任务状态表达任务从建单到闭环的进度，不再用缺料阻断建工单；状态收敛为待建工单、部分建单、已建单、已完成。物料齐套单独作为备料状态展示，可提示可齐套、部分可生产或缺料；缺料影响后续释放、领料和开工，不阻止先创建计划工单。
- 生产任务底层待办：销售订单缺口自动生成任务、可用库存与安全库存计算、按启用配方计算物料需求、预估损耗叠加、物料齐套判断、采购/来料质检联动、建工单前校验都应接真实数据；当前前端只先固定入口和字段边界。

## 1. 快速原则

- `GW-01` 页面职责先行：工作台回答“今天做什么”；列表回答“找到哪张单”；详情页回答“处理这张单”；只读查询回答“查什么、判断什么”；主数据回答“能否被正确引用”。
- `GW-02` 一致性不是照抄字段，而是复用判断方法：当前角色、用户任务、关键信号、下一步、动作归位、摘要边界。
- `GW-03` 列表就是列表，不承担完整工作台职责；不要为了“看起来丰富”把详情字段全搬上来。
- `GW-04` 单据详情承载主操作、字段填写、流程推进、附件、打印/PDF、日志等；列表默认不放操作列。
- `GW-05` 前端原型先统一界面和交互口径；真实状态机、库存、生产、质检、发票、收付款、权限审计放到底层待办。
- `GW-06` 页面里不要出现“原型、后续接入、后端接口”等实现口吻；这些写进本文件，不写到业务界面。

## 2. 每轮优化检查清单

### 2.1 页面职责

- 判断页面类型：业务列表、单据详情、新建/编辑、只读查询、主数据、报表、工作台。
- 判断使用者：销售、采购、仓库、生产、质检、财务、管理员分别需要看到什么。
- 判断用户任务：查找、决策、推进、登记、复核、追溯、维护，不能混成一个页面全做。
- 判断数据流向：单据从哪里来，流向哪里，哪些状态由当前模块处理，哪些只是其他模块摘要。

### 2.2 列表

- `GW-L1` 高频业务列表默认整行可点击进详情，不放“操作/查看”列。
- `GW-L2` 有强流程状态的业务列表，状态列固定右侧，并在状态下显示“下一步”；表格主体不再重复状态列。
- `GW-L3` 默认排序按业务待办优先：草稿/待处理靠前，已完成倒数第二，已作废最后；同状态内按日期或更新时间排序。
- `GW-L4` 有责任分派的业务显示负责人/经办人，不显示创建人；创建和修改信息留到日志。
- `GW-L5` 有附件能力的业务列表保留附件列，只显示数量/有无/关键标记。
- `GW-L6` 左侧搜索承接单号、客户、供应商、负责人、物料等自由关键字；筛选弹窗只放状态多选、日期范围和少量固定维度下拉。
- `GW-L7` 列表 hover 轻微凸显，不改变行高，不造成布局跳动。
- `GW-L8` 长文本要截断或摘要化，完整内容放详情页。

### 2.3 单据

- `GW-D1` 右侧如果有流程节点，永远放第一块，标题统一叫“流程节点”。
- `GW-D2` 右侧只放真实摘要：流程节点、财务摘要、交付/库存摘要、关联单据、附件、风险提示等；不要放重复说明或低价值检查卡。
- `GW-D3` 未确认草稿允许删除；进入跨部门流转后一般不直接删除，只做作废、异常或售后。
- `GW-D4` 必填规则采用“字段标签标必填 + 保存/确认时就近提示缺失项”，不要一进页面就大面积报错。
- `GW-D5` 删除列表操作列后，必须反查详情页是否补齐主操作，避免业务动作丢失。
- `GW-D6` 跨部门信息在当前单据中以摘要和追踪入口为主，不替代其他模块的完整操作。
- `GW-D7` 详情页按钮尽量短名：新建、保存、提交、确认、入库、出库、打印、PDF、日志、悬浮、更多。危险动作不要过度压缩，例如“删除草稿”。

### 2.4 字段与信息

- `GW-F1` 每一处文字都要判断语义是否准确、易懂、贴近业务，而不是贴近实现。
- `GW-F2` 同一业务概念只保留一个用户可见名称；相似位置不要混用“流程节点/状态流转/流转状态/状态节点”。
- `GW-F3` 同一底层状态在不同模块可以有不同业务表达，例如仓库显示“已出库”，销售订单侧显示“待签收”。
- `GW-F4` 每个字段都要判断是否是噪音、重复、对当前角色无效、影响判断；无效就清理，缺失的有效信息要补。
- `GW-F5` 引用选择器只展示决策摘要。客户、物料、供应商等不要展示启用状态、后台条款、内部属性等无关元信息。
- `GW-F6` 少量固定枚举用下拉；客户、供应商、物料、人员等候选会增长的对象用可搜索引用选择。
- `GW-F7` 固定枚举不要在每个下拉里塞“管理选项”；统一由系统“选项字典”维护，业务页只选择。
- `GW-F8` 主数据默认信息要能带入单据，例如客户默认物流/收货信息、供应商默认交付/付款/税率；带入后仍允许本单修改。

### 2.5 视觉、交互与验证

- `GW-U1` 相同类型板块字段规则要稳定：基本信息、明细、金额/数量汇总、商务/采购条款、物流/收发货、附件等。
- `GW-U2` 表头、内容、固定列要同时校验表头高度、行高、滚动容器和窄屏表现。
- `GW-U3` 悬浮参考窗优先于固定分屏：右上角悬浮、可收起/展开/关闭、主页面路由切换不影响参考窗；入口只放详情页，新建/编辑页不放。
- `GW-U4` 只读参考页不做流程节点、下一步、附件上传和主操作按钮。价格记录、库存速查、库存查询、库存流水都按只读页处理。
- `GW-U5` 巡检详情页不要猜样本编号，先从当前列表取真实可见行再进详情。
- `GW-U6` 旧链接或不存在编码必须显示“未找到”空态，不能显示一张空白但可编辑/可悬浮的假详情。
- `GW-U7` 已废弃或合并的旧入口要自然收敛，能重定向就重定向，不让用户进入无权限页或旧空页。
- `GW-U8` 每轮优化必须用浏览器实际检查列表、详情、新建/编辑、选择弹窗、按钮点击、滚动、固定列和空态；不能只看代码。
- `GW-U9` 当前系统数据都是测试数据。原型巡检和交互验证可以新增、修改、删除测试单据；真实上线前再补权限、审计和数据保护。

## 3. 标准页面模式

### 3.1 业务列表模式

- 顶部：页面标题、搜索、排序、筛选、导出、新建按钮。
- 表格主体：核心摘要字段，不放操作列；行点击进入详情。
- 固定状态列：状态 + 下一步；和主体行高对齐。
- 空态：说明当前没有数据，并给出合理入口，不出现技术错误口吻。

### 3.2 单据详情/编辑模式

- 顶部：返回、标题、主状态/下一步、主操作按钮。
- 主区域：基本信息、明细、金额/数量汇总、业务条款、物流/收发货、备注/附件。
- 右侧：流程节点第一；后续按价值放财务摘要、交付/库存摘要、关联单据、附件、风险提示。
- 编辑/新建：保留必要动作，不放悬浮参考；草稿类可删除，已流转单据走作废或更多动作。

### 3.3 只读查询模式

- 适用：价格记录、销售库存速查、仓库库存查询、库存流水、后续报表。
- 目标：快速查到结果并做判断，不推进流程，不上传附件。
- 可以有视角切换、钻取详情、导出；不要放流程节点和主操作按钮。

### 3.4 主数据模式

- 目标：找得到、选得准、维护清楚、能被业务单据正确带入。
- 列表保留引用判断摘要，不搬完整档案。
- 详情右侧不放流程节点，可放使用状态、摘要、附件、最近维护等。
- 状态统一叫“使用状态”，表达能否继续被新业务引用。

## 4. 已优化模块样板

### 4.1 销售

- `SO-01` 销售订单流程口径：草稿 -> 待发货 / 生产中 -> 待签收 -> 待开票 -> 待收款 -> 已完成；异常用主状态 + 异常标记，不扩成过多主状态。
- `SO-02` 销售订单列表：行点击进详情；显示负责人；状态固定右侧；附件列保留；不显示创建人。
- `SO-03` 销售订单详情：草稿可删除；确认、作废、打印、PDF、日志放详情；变更、异常、作废、售后等低频动作收进“更多”；不单独做异常/变更记录块，统一写日志。
- `SO-04` 销售侧不叫“备货中”；仓库已出库但客户未确认时，销售侧叫“待签收”。
- `SO-05` 销售订单保留财务摘要，但销售不直接执行财务操作。
- `SO-06` 商务条款包含交付日期、交付方式、付款方式、计价口径、税率、运费承担、条款正文；物流方式统一为客户自提、本厂配送、整车货运、拼车物流、快递快运。
- `SO-07` 销售确认签收第一版点击按钮即可，可加轻确认；有异常时走更多/售后。
- `SQ-01` 报价单是价格提案，不承担履约责任分派；不填负责人，列表不显示负责人。
- `SQ-02` 报价单商务条款和销售订单保持口径；详情不需要“报价检查”类重复卡。
- `SR-01` “发货追踪”改名为“交付追踪”，定位为销售侧交付进度视图，不替代仓库出库。
- `SP-01` 销售价格记录是只读参考页，不需要附件。
- `SSK-01` 成品库存速查是销售侧只读参考页，只展示销售判断所需：销售物料、总可用、已锁定、待补充、出库占用、现货可承诺、补充后可承诺。

### 4.2 采购

- `PUR-REQ-01` 采购申请关注内部需求是否被批准和转采购，不是供应商履约。
- `PUR-REQ-02` 采购申请草稿可删除；提交后走审批、驳回、转物料采购。
- `PUR-REQ-03` 采购申请先聚焦普通物料采购需求；资产采购改走独立菜单和单据。
- `PUR-PO-01` “采购订单”正式改名为“物料采购”。确认后真正待办是到货、入库、开票、付款，不单独强调“已确认”节点。
- `PUR-PO-02` 物料采购流程建议：草稿 -> 待到货 -> 待入库/部分入库 -> 待开票 -> 待付款 -> 已完成；作废最后。
- `PUR-PO-03` 是否需要质检由物料质检属性决定，不作为所有物料采购的固定节点。
- `PUR-PO-04` 物料采购列表显示供应商、经办人、预计到货、金额、入库/发票/付款摘要、附件、状态下一步；不显示创建人。
- `PUR-PRICE-01` 采购价格记录是只读参考页，不需要附件。
- `PUR-ASSET-01` 资产采购独立成和物料采购并列的菜单，不进入普通库存入库节点。
- `PUR-ASSET-02` 资产采购关注资产名称、类别、规格型号、预算、用途、申请部门、验收负责人、供应商、交付/验收状态；验收完成后应生成资产档案。

### 4.3 仓库

- `WH-01` 仓库列表是作业入口和追踪列表；库存查询/库存流水是参考页，二者不要混用流程设计。
- `WH-02` 仓库业务列表有附件能力时保留附件列；状态固定右侧并显示下一步。
- `WH-03` 仓库单据右侧流程节点第一，后续放单据摘要、库存影响、附件、关联单据。
- `WH-04` 采购入库按物料质检属性分流：需要质检的先待质检，合格后入库；免检物料核对后可直接入库。
- `WH-05` 销售出库流程：待受理 -> 待拣货 -> 待复核 -> 已出库；销售订单侧对应待发货/待签收，不照搬仓库状态。
- `WH-06` 生产出入库拆成三个操作菜单：生产领料、生产退料、完工入库；不保留生产出入库总览。
- `WH-07` 生产领料关注生产任务、应领/已领/欠料、领料仓、线边仓、是否允许超领。
- `WH-08` 生产退料关注原领料记录、退料原因、可退数量、退回仓、是否影响工单用料。
- `WH-09` 完工入库关注生产任务、成品、合格/不良数量、入库仓、批次、质检/放行。
- `WH-10` 其他出入库流程建议：草稿 -> 待审核 -> 待过账 -> 已过账。
- `WH-11` 库存查询回答当前有什么、在哪、能不能用；库存流水回答为什么变动。
- `WH-12` 批次追溯不单独做菜单，合并进库存查询；库存查询使用物料/库位/批次视角 + 选中行详情。
- `WH-13` 库存查询默认以物料为主体，选中物料后在详情里看仓库/库位、批次、状态和最近流水；不要让同一物料因批次拆成很多主行导致用户手工汇总。
- `WH-14` 库存查询是高频判断页，少放口径说明、总览大卡和教学文案；关键信息放在列表行和详情摘要里。

### 4.4 基础资料

- `MD-01` 基础资料不是流程单据，不套流程节点、下一步和流转状态。
- `MD-02` 主数据状态统一叫“使用状态”；启用/停用/维护中表达能否继续被引用。
- `MD-03` 物料“是否销售”只限制销售端选品；采购端不因“成品/非成品”排除候选。
- `MD-04` 物料分类是分类，成品只是分类之一；编码全部自动生成。
- `MD-05` 物料库存管理暂保留“批次管理 / 不追踪批次”，不保留未落地的“按卷管理”。
- `MD-06` 客户维护默认物流方式、收货人、联系方式、收货地址；带入销售单据后允许修改。
- `MD-07` 供应商维护默认交付方式、付款方式、税率；后续带入物料采购。
- `MD-08` 开票资料是发票专用信息，标准字段至少包含抬头、税号、联系电话、注册地址、开户行、银行账号。
- `MD-09` “设备”正式改名为“资产”；资产资料关注编号、名称、类别、规格型号、使用部门、负责人、位置、启用日期、使用状态。
- `MD-10` 单位、部门、员工、公司、产线等轻量资料保持简单列表 + 维护页；只展示业务引用需要的信息。

### 4.5 售后与悬浮参考

- `AFTER-01` 销售售后、采购售后都作为独立入口，不只在原单里追加备注。
- `AFTER-02` 售后列表按统一业务列表处理：状态固定右侧，表格主体不重复状态列。
- `AFTER-03` 售后状态排序：待受理 -> 处理中 -> 待确认 -> 已关闭。
- `AFTER-04` 售后字段关注原因分类、责任/协同、金额影响、关联原单、退换补/退款/扣款处理、附件和日志。
- `REF-01` 悬浮参考窗入口放详情页；新建/编辑页不放；主页面切换时参考窗保持独立。

### 4.6 电商与平台渠道

- `ECOM-01` 电商模块建议独立成一级模块，定位为“平台渠道层”，不塞进销售模块内部；天猫 API 暂不可用时，第一版负责店铺建档、SKU 映射、订单导入、库存表导出、发货表导出、售后导入和平台对账。
- `ECOM-02` 电商订单进入 ERP 后仍应转销售订单履约；仓库负责拣货、出库和物流结果，质检负责退货判定，财务负责到账、退款和平台账单核对。
- `ECOM-03` 电商库存表不能直接用总库存，应按合格成品库存、已预留、渠道占用和安全库存计算可售数；异常差异需要人工复核后再导出给平台后台。
- `ECOM-04` 电商售后只是平台入口，退款、退货、补发、退货质检和二次入库要继续落到销售售后、仓库、质检和财务。
- `ECOM-05` 第一版前端先做渠道台账和文件导入/导出待办，不在界面里暴露“接口未接入”等实现说明；后续平台自动对接、签名、幂等、消息队列、重试和审计放到底层联动待办。

## 5. 生产与质检历史检查要点（已完成，保留作回归参考）

> 2026-07-08 补充：本节是生产/质检的业务原则，不是最新逐页巡检清单。实际执行时必须同时参考 `six-module-ui-consistency-audit.md` 第 79 节和 `production-quality-frontend-handoff.md`，逐页检查列表、详情、规则、新建、编辑、变更页，以及按钮、hover、focus、disabled、点击前后、toast、confirm、日志、附件、右侧摘要和移动端表现。

### 5.1 生产模块关注点

- `PRD-01` 先重新判断生产模块是否需要“工作台 + 列表 + 单据详情”三层；工作台处理现场任务，列表用于查找，详情用于单据推进。
- `PRD-02` 生产任务、生产工单、流转批次、工艺模板、工序节点、异常闭环要分清职责，不要混成一个页面。
- `PRD-03` 生产任务承接销售缺货/计划需求，判断是否需要生产、缺料、预计完工、优先级。
- `PRD-04` 生产工单关注配方、应领/已领、产线、工序、计划数量、实际产出、损耗和报工。工单详情必须展示当前工单采用的配方快照和工艺快照，包括配方版本、关键用料、预估损耗、工艺模板、温区和工序编排；后端落地时不能只保存配方/工艺编号，应在工单创建或释放时保存快照，避免后续版本调整影响历史工单。
- `PRD-05` 流转批次关注批次号、工序进度、质检节点、合格/不良、返工/报废、入库状态。
- `PRD-06` 生产异常关注缺料、设备/资产、质量、返工、报废、停线和责任对象；不要只做一条备注。
- `PRD-07` 生产与仓库的边界：领料、退料、完工入库由仓库单据执行；生产侧展示需求、状态和结果摘要。
- `PRD-08` 生产中的不良统计要能追溯到工单、工序、产线/班组、操作人、物料批次、设备/资产。
- `PRD-09` 损耗台账确认放在生产模块独立菜单，统一承接生产报工、复绕、包装、异常事件和质检判定产生的 kg 损耗；质检负责判定和来源，生产负责损耗汇总、责任追溯和统计。页面按纯列表记录类处理，不作为独立业务单据流，不提供现场操作按钮和详情页。
- `PRD-10` 物料配方是生产规则页，不是业务流程单据。它只维护适用成品、自动版本、单位、每单位净重、明细用量、任务层面的预估损耗和备注；配方明细不写每单位损耗，损耗独立到“预估损耗”区；配方明细和预估损耗都禁止重复物料。
- `PRD-11` 工序节点是工艺模板和生产工单可引用的系统预设动作库，不是现场流转批次记录，也不是用户日常维护资料。节点编号、节点名称和动作配置均由系统固定，前端不提供新增、复制、编辑动作或停用入口；列表按能力说明表处理，只显示工序节点、触发动作、完成条件和异常规则，不再显示更新列和独立维护状态列。详情页只用于查看触发时机、执行方、生成内容、完成事件、阻断关系、质检标准和异常规则。作业提示、核心设备、控制点、常见问题等现场资料放到工艺模板的工序编排中维护。
- `PRD-12` 提示类要求不单独占系统工序；如果“烘干、清洁、确认温度”等只是文字提醒，应合并到前后真实动作节点的作业提示里。只有会生成待办、等待结果、阻断流转、生成单据/任务或需要现场确认的事项，才作为独立工序动作或独立工序节点。
- `PRD-13` 同一成品允许多个物料配方版本共存，但同时只能有 1 个启用版本。版本号由系统根据该成品已有最大版本递增生成，不按版本数量补空号；如果启用当前配方会导致同一成品存在 2 个及以上启用版本，前端保存/提交必须拦截并提示，后端也必须有唯一约束兜底。
- `PRD-14` 生产侧新增“备料申请”入口，用于任务缺口补料、临时备料、试产备料、损耗补料和返工补料。生产任务可提前发现采购缺口并发起备料申请；仓库先判断可备料/调拨数量，库存不足部分再生成采购模块的采购申请。生产工单不直接发起采购申请，也不因缺料阻止创建计划工单，但实际释放/领料/开工数量必须受可用库存约束。

### 5.2 质检模块关注点

- `QC-01` 质检模块至少区分来料质检、生产质检、质量巡检、质检标准、不良记录；不要把所有质检揉成一个列表。
- `QC-02` 来料质检承接采购到货/采购入库，结果决定是否放行入库、退货、让步接收或补检。
- `QC-03` 生产质检承接工单/流转批次，覆盖首检、报工全检、成品质检、入库抽检等固定质检节点；不要把主动巡检混入生产质检列表。
- `QC-04` 质检标准是主数据/规则，不是流程单据；重点维护适用物料、检验项目、标准、频次、判定方式。
- `QC-05` 不良记录要统一原因分类、责任对象、处置动作、影响数量、影响金额、关联批次/工单/供应商/客户。
- `QC-06` 不良统计与责任追溯后续应区分人为、设备/资产、物料、工艺、来料、客户要求等原因，避免简单归咎单一人员或部门。
- `QC-07` 质检结果要影响仓库、采购、生产、销售售后和财务成本，但第一版前端只做清晰摘要和入口。
- `QC-08` 质量巡检用于记录非固定节点的现场主动检查、随机抽查、风险预警、整改和复查；可关联工单/批次/产线，但默认不阻断生产流转，异常时再转不良记录、生产异常或损耗台账。

## 6. 跨模块底层待办

- `X-01` 统一状态机：销售、采购、仓库、生产、质检、财务之间要有明确状态来源和状态映射。
- `X-02` 统一附件模型：附件列、附件摘要、附件上传、附件权限、附件数量和关联单据要一致。
- `X-03` 统一日志/流转记录：保存、提交、确认、审核、作废、出入库、开票、收付款等都要可追溯。
- `X-04` 统一主数据默认值：客户/供应商的联系人、地址、物流/交付、付款、税率等应能带入业务单据。
- `X-05` 统一财务摘要：销售侧看应收/开票/收款，采购侧看应付/收票/付款；业务单据只展示摘要和入口。
- `X-06` 统一库存联动：订单确认、采购入库、销售出库、生产领料/退料/完工、调拨、盘点调整共同影响库存余额、锁定和可承诺量。
- `X-07` 统一权限：当前角色能看什么、能操作什么、能跳转哪里，要随模块职责控制。
- `X-08` 统一导出/打印/PDF：按钮命名、生成方式、文件内容和权限需要一致。
- `X-09` 统一售后闭环：销售/采购售后联动库存、财务、质检和客户/供应商记录。
- `X-10` 统一不良统计与责任追溯：生产和质检不良要能按工单、工序、批次、人员、资产、原因和处置追溯。
- `X-11` 统一选项字典：系统模块已做原型，后续要真实接入各固定枚举下拉。
- `X-12` 资产采购底层应拆独立模型；验收完成后生成资产档案，折旧、维护、报废后续扩展。
- `X-13` 允许部分发货、部分入库、部分开票、部分收付款时，需要状态机、列表摘要和库存/财务联动一起设计。
- `X-14` 电商平台联动需要独立集成层：第一阶段先支持平台后台导出文件的导入/导出和重复校验；后续若接自动对接，再补平台授权、SKU 映射、订单幂等、库存推送锁、物流回传、售后同步、平台账单导入、失败重试和操作审计。
- `X-15` 生产工序状态机需要“工序实例 + 动作实例”两层模型。工艺模板排好工序顺序后，生产任务创建时必须快照当时的工序和动作配置；运行中进入工序时按动作配置生成待办/按钮/质检任务，动作完成后再判断是否自动推进下一工序。
- `X-16` 工序动作生成必须幂等。刷新页面、重复进入工序、接口重试或消息重放时，不能重复生成待发料、待质检、报工入口或入库待办；每个动作实例要有唯一键、状态、执行方、完成事件和操作日志。
- `X-17` 仓库发料动作不能只有完成/未完成。后续底层至少要支持待发料、部分发料、缺料中、已发料、取消/退回，并能把缺料、替代料、部分发料结果回写给生产工序状态机。
- `X-18` 质检类工序动作要统一合格、不合格、让步放行、返工、报废、复检、待处置等后续状态。未放行的阻断动作不能推进下一工序；放行、返工或异常闭环必须留下日志和责任追溯。
- `X-19` 物料配方版本要有后端一致性约束：同一成品只能有 1 个启用配方，版本号按最大版本递增生成，接口需处理多人并发新建/启用导致的冲突；生产任务/工单创建时必须快照当时的配方编号、版本、明细用量和预估损耗，历史任务不能被后续配方版本切换影响。
- `X-20`（已由 2026-07-28 自动分流方案取代）备料申请提交后由系统按统一可用库存事实计算覆盖量与缺口，缺口幂等生成采购申请；不再生成仓库受理待办。仓库只承接工单释放后的真实领料任务。

## 7. 已定问题与当前结论

- `Q-01` 首页后续做统一待办工作台，聚合跨模块待办、风险/逾期和最近处理。
- `Q-02` 销售订单签收第一版点按钮即可，不强制上传签收凭证。
- `Q-03` 采购质检由物料属性决定，需要质检的先质检后入库，免检的核对后直接入库。
- `Q-04` 外购成品和自制成品共用物料主数据；销售端按“是否销售”筛选，采购端后续按采购属性判断。
- `Q-05` 资产采购独立菜单；物料采购菜单不再承担资产采购。
- `Q-06` 生产出入库拆成生产领料、生产退料、完工入库，不保留总览。
- `Q-07` 仓库库存只保留库存查询和库存流水；批次追溯并入库存查询批次视角。
- `Q-08` 销售、采购、仓库、基础资料目前已按前端原型层面收敛；后续等生产/质检优化后，再做跨模块联动复查。
- `Q-09` 生产模块菜单现确认为：生产工作台、生产任务、生产工单、流转批次、损耗台账、物料配方、工艺模板、工序节点、异常闭环。损耗台账是本轮新增的生产侧统计与责任追溯入口，按纯列表记录页处理；领料/退料/入库仍回仓库单据执行。
- `Q-10` 质检标准按主数据/规则维护，不走质检流程单据；不良记录单据补原因分类、责任对象、影响数量、影响金额/成本摘要。
- `Q-11` 生产/质检列表继续向已优化销售、仓库列表靠拢：列表负责找单和显示下一步，整行可进入详情；流程推进、维护、异常闭环等动作放到详情/维护面板，不在表格主体堆操作按钮。
- `Q-12` 本轮确认：生产业务列表行进入 `/production/:page/:code` 单据页，业务单据详情页右侧第一块为流程节点，损耗台账除外，它只有列表台账没有详情页；质检列表移除操作列，状态固定右侧，异常处理/作废/编辑等动作回到质检单据页，质检标准继续作为规则维护面板。
- `Q-13` 生产、质检列表必须使用与销售/仓库一致的 `quote-table-shell + quote-status-column + quote-card-list` 结构；单据页统一为左右两栏 `quote-form-grid`，右侧流程节点第一，动作文案统一“打印 / PDF / 日志”。
- `Q-14` 本轮确认：生产列表页头和列表外层不再自成卡片，向销售/仓库的 `table-title quote-title + BusinessListToolbar + quote-table-shell` 层级收敛；生产、质检单据右侧摘要统一补“附件”块，放在“单据摘要”之后、“日志/责任追溯”之前。
- `Q-15` 本轮确认：生产、质检业务列表按有附件能力的单据保留“附件”列、移动端卡片保留附件数量、导出带附件数；质检标准、生产规则类资料不虚构附件和流程节点，列表侧使用“使用状态 / 维护动作”口径。生产、质检详情页统一补“悬浮”参考入口，日志按钮打开统一日志面板；配方、工艺模板、工序节点、质检标准这类规则页右侧第一块叫“维护状态”，不叫“流程节点/下一步”。
- `Q-16` 生产模块内部可以继续用 `quality-standards` 表示“质检与标准”职责，但用户可见的质检业务归入独立质检模块；旧的 `/production/quality*` 与 `/production/quality-standards*` 路径必须自然重定向到 `/quality/production` 或 `/quality/standards`，不能显示菜单权限拦截或空详情。
- `Q-17` 本轮跨模块复查确认：销售售后、采购售后不能只做列表和来源原单链接，必须提供独立售后详情页；列表行、状态列和移动端卡片进入 `/sales/after-sales/:code` 或 `/purchase/after-sales/:code`，详情页保留悬浮、打印、PDF、日志、编辑和状态推进，右侧第一块为流程节点。
- `Q-18` 本轮口径清理：详情页锁定态按钮统一使用“已锁定”，不再显示“只读状态”；生产质检的类型/标准预选面板可以保留，但最终“新建质检单”必须用主操作样式。
- `Q-19` 文档口径确认：本文保留为方案池和业务边界；生产/质检前端专项的最新执行目标、逐页检查要求和未完成项以 `six-module-ui-consistency-audit.md` 第 79 节、`production-quality-frontend-handoff.md` 为准。
- `Q-20` 新对话执行口径确认：生产/质检不能只按本文第 5 节做业务字段判断，还必须对照销售、采购、仓库、基础资料已优化页面逐页检查视觉效果、填选效果、鼠标悬停、焦点、禁用、点击前后、toast、confirm、日志、附件、右侧摘要、移动端和所有共性控件一致性。
- `Q-21` 本轮确认：质检模块新增 `质量巡检` 独立菜单，路径 `/quality/patrol`；它是主动巡检/整改复查记录，不替代来料质检、生产固定质检、质检标准或不良记录。
- `Q-22` 本轮确认：电商按独立一级模块试做，路径前缀 `/ecommerce`；天猫 API 暂不可用时，第一版菜单包括电商工作台、店铺管理、SKU 映射、电商订单、库存导出、发货导出、售后导入和平台对账。它是渠道对接层，不替代销售、仓库、质检或财务的 ERP 履约单据。
- `Q-23` 本轮确认：物料配方不需要手填配方名称，配方编号 + 版本号足够识别；单位来自适用成品物料属性。配方明细只表达投料占比或固定用量，损耗按每次生产任务单独维护为预估损耗。
- `Q-24` 本轮确认：配方明细和预估损耗均禁止重复物料。重复物料不自动合并，避免把投料占比、固定用量或损耗含义合错；选择时隐藏已选物料，提交时再次校验历史脏数据。
- `Q-25` 本轮确认：配方版本号不手填，选择适用成品后自动生成；生成逻辑按已有最大版本号 + 1，不按版本数量补空号。同一成品可有多个历史/停用版本，但同时只能启用 1 个版本。
- `Q-26` 本轮确认：换配方不应通过复制一个名称型号相同但编码不同的成品来实现；成品编码用于区分库存、销售、质检和交付意义上的物料，配方版本用于区分生产方法。只有产品身份、包装、标签、证书、质检标准、库存不可替代性等真实变化时，才新建成品编码。
- `Q-27` 本轮确认：工序节点前端按系统预设能力清单处理。列表隐藏新建入口，去掉更新列和右侧维护状态列，改为“工序节点 / 触发动作 / 完成条件 / 异常规则”；详情页隐藏编辑/复制/停用/复核等变更动作，直接访问新建页重定向回列表；节点名称、编号、动作配置不可由用户修改。真实待办生成、按钮执行、质检任务生成、仓库发料、自动推进和异常分支放到底层状态机实现，不在当前前端原型里硬做。
- `Q-28` 工艺模板继续按规则资料优化；温区名称和单位默认，避免让用户手填系统可推导的符号/名称。工序编排选择固定系统工序节点，同时用连续工艺卡行维护核心设备、作业内容、控制点和常见问题；序号只做左上角角标，工序节点和系统动作合并为顶部节点头，作业资料顶到内容左侧，避免把现场说明挤在表格列或左侧轨道中；真实执行仍由生产任务/工序状态机快照承接。
- `Q-29` 本轮确认：生产任务详情页不再以单一成品的库存缺口/建议生产为中心，而要对齐生产工作台“任务建单”待办详情。生产任务是需求包，至少展示来源单据、负责人、优先级、创建时间、交期、需求总量、入库进度、成品明细、预估物料与备料、关联工单；来源单据不可手填，销售订单来源自动带入交期和负责人，手动新建无来源单据；优先级仅正常/加急，建单状态由流程和数据控制，新建/编辑表单不展示状态和创建时间这类系统字段；建单状态不再包含待评估/待备料，缺料只进入物料备料状态，允许先建计划工单，执行释放、领料、开工前再做缺料校验。
- `Q-30` 本轮新增生产“备料申请”原型：菜单放在生产任务之后；生产任务详情在存在需采购物料时提供“备料申请”动作，新建页可从任务缺口带出物料，也可手动新建临时备料。备料申请主区只保留申请基础和备料明细，状态摘要放右侧；明细禁止重复物料，申请数量必须大于 0，需采购数量可按申请数量减当前库存自动计算并允许人工修正。
- `Q-31` 生产任务列表按“需求包”重排为：生产任务、来源、成品需求、工单/进度、物料备料，任务状态继续固定在右侧；第一列第二行只放优先级，来源列第二行用“负责人·姓名”，成品需求第二行放成品摘要和项数，工单/进度第一行只放“x个工单”，物料备料第一行放缺料/齐套数量、第二行放备料申请数。生产任务详情的“预估物料与备料”区直接提供备料申请入口，并展示已发起备料申请、状态、采购申请关联和每个物料的已申请数量。
- `Q-32` 生产任务详情主区不再放重复的胶囊汇总条，也不再放顶部“建单提示”说明条：成品明细、预估物料与备料、相关备料申请都以表格和右侧摘要承载判断信息；右侧流程节点补齐“已完成”，当入库数量达到需求数量时任务可进入闭环状态。新建/编辑任务时，成品明细表只显示可填写的成品和需求数量，不显示已建工单、已入库、待建工单等结果字段；手动新建任务不展示空的来源单据和相关备料申请面板。
- `Q-33` 生产任务详情的相关备料申请卡片应按“申请单信息 / 申请物料与数量 / 承接状态”三段展示。申请数量表达生产侧提出的备料需求；是否需要采购由仓库/采购承接状态表达，不应和申请数量并列成“申请 X、需采购 X”造成概念重复。备料申请按钮使用明确的“新建申请”，避免小按钮在标题右侧显得像被挤压的临时控件。
- `Q-34` 生产任务“预估物料与备料”表按一个字段一列展示：物料只显示名称和编码，来料质检不放在物料名称下；列顺序为预估需求、可用库存、待检、锁定、缺口、已申请、备料状态，让申请信息紧跟缺口判断。相关备料申请卡片继续减噪，只保留申请单号、需求日期、物料数量和承接状态，不重复显示申请类型、申请数量和采购申请单号。
- `Q-35` 详情页区块内动作按钮必须复用系统既有 `secondary-action compact-action` / `primary-action` 样式，不再为单个业务区块新建局部按钮外观。生产任务详情的关联工单区需要同时提供“新建工单”入口和已有工单详情入口；从生产任务新建工单时通过任务号带上下文，后续工单表单可继续自动带入成品、数量、配方和工艺。
- `Q-35A` 生产执行链继续收口为“生产任务 -> 计划工单 -> 释放批次 -> 流转批次 -> 质检/入库”：生产任务和详情统一使用“待建工单”，生产工单统一使用“待释放/释放到现场”，工单详情下钻展示关联流转批次，流转批次详情使用“释放数量、已发料、已报工、已入库、待入库、不良数量、当前工序、质检与下一步”。生产侧 `QC2-...` 质检任务已桥接到质检模块生产质检详情，流转批次详情可直接跳转 `/quality/production/:code`；真实回写、放行阻断和库存入库仍属于后续底层状态机。
- `Q-35B` 生产补料链的 `IQC2-...` 来料质检任务已桥接到质检模块来料质检详情，入口为 `/quality/incoming/:code`。来料质检详情用采购入库/到货作为来源类型，质检仓表达暂存位置，供应商缺失时显示待确认供应商；合格放行后应进入可用库存或生产领料，不能沿用生产流转批次的回写口径。
- `Q-35C` 生产工单详情已补配方快照和工艺快照入口，并在物料储备中优先沿用配方物料单位；原料按 kg，包材按个/套等物料单位展示，不再被成品单位误导。真实后端仍需在工单创建或释放时保存配方、工艺和单位换算快照。
- `Q-35D` 生产工单列表应只服务执行扫描：编号列下方显示工艺模板，不重复显示状态；当前节点列使用短批次摘要，完整流转批次、报工和入库明细保留在工单详情。列表第六列不能复用附件列样式，避免当前节点和批次摘要拥挤、错位。
- `Q-36` 六大模块列表页通用工具栏统一使用 `BusinessListToolbar` 的“搜索 / 排序 / 筛选 / 导出”口径：搜索框 title 为“搜索当前列表”，排序弹层标题为“排序方式”，筛选按钮 title 为“筛选当前列表”，导出弹层标题为“导出范围”，导出说明为“按当前搜索、筛选和排序导出”。本轮发现该组件曾存在异常编码和导出文案乱码风险，已修复并用浏览器复核销售、采购、仓库、生产、质检、基础资料代表列表；后续新增列表页必须复用该组件或保持同等文案、按钮位置、hover/focus/disabled 样式和弹层结构。
- `Q-37` 六大模块巡检的共性标准继续固定为：列表页负责找单和状态扫描，详情页负责推进单据，规则/主数据页不伪造流程节点；有流程的详情页右侧第一块为“流程节点”，规则页右侧使用“维护状态/规则摘要”，新建页不强行展示不存在的摘要；附件区、日志、打印、PDF、更多操作和保存/提交按钮复用系统既有按钮层级，不新建局部外观。任何新增字段必须先判断是否帮助当前角色决策或操作，否则记录到日志/摘要/后端待办，不放进主表单。
- `Q-38` 当前前端巡检只能证明可见原型层的布局、文案、菜单和交互入口大体一致，不能替代真实状态机、权限矩阵、库存齐套、采购联动、质检放行、工单创建和附件上传的后端校验。涉及这些约束时，前端可以展示入口和提示，但最终必须由后端幂等接口、唯一约束和操作日志兜底。
- `Q-39` 质检新建页附件区按新建态减噪处理：新建来料质检/生产质检只展示上传入口和上传范围提示，不展示“附件数量 0 个”或“归档范围 系统自动生成”；详情/编辑态才展示附件数量和归档范围，保证追溯信息存在但不干扰建单。
- `Q-40` 六大模块通用列表搜索框必须有可识别名称和清晰聚焦反馈；排序、筛选、导出、主次动作及更多菜单保持统一的键盘焦点样式。共用日志弹层和引用选择器打开后应把焦点移入弹层，Esc/关闭后把焦点还给原触发按钮，避免键盘操作丢失当前位置。

- `Q-58` 明细行删除、上移/下移、展开和更多等纯图标按钮不能只依赖图形或 hover `title`：必须有明确 `aria-label`，并保留 tooltip。按钮因“至少保留一行/一项”而禁用时，tooltip 应说明禁用原因，不能继续提示“删除”；新增第二行后恢复可执行动作提示。带可见文字的顶部保存、提交、上传等按钮不重复添加冗余 aria-label。

- `Q-60` 视觉红星和错误红框不能替代控件语义。共用 `ReferencePicker` 必须支持 required 契约：可编辑按钮使用 `aria-required=true`，只读值使用有名称的 `role=textbox + aria-readonly=true` 并保留 required；可选来源单据不得误标。资产采购/申请的验收负责人按采购类型动态必填，通用基础资料引用按字段配置动态传入。原生 input/select/textarea 的必填语义仍需后续按同一原则逐步补齐。
