# Filatrix ERP Web 页面设计基线

> 日期：2026-07-16  
> 优先级：本文件服从 `erp-web-prototype-blueprint.md` 和 `erp-web-business-fact-model.md`；优化清单只用于检查遗漏。  
> 当前阶段：先稳定流程、页面职责、内容和布局，再冻结交互；未冻结页面不继续扩展底层能力。

## 1. 设计顺序

每个模块固定按以下顺序推进：

1. 画清正常流程、异常流程、角色和跨模块交接点。
2. 明确页面类型和唯一职责。
3. 确定页面必须显示的判断信息、低频详情和应删除噪音。
4. 确定主操作、次操作、下一步和禁用原因。
5. 完成桌面与移动端前端原型，在浏览器中验收。
6. 用户确认后标记为“交互已冻结”。
7. 只为已冻结流程补充必要业务命令；数据库、事务和部署后置。

页面按钮、抽屉或文案尚未冻结时，禁止继续按临时 UI 扩展服务端接口。

## 2. 页面类型与职责

| 页面类型 | 首要问题 | 必须包含 | 不应包含 |
| --- | --- | --- | --- |
| 列表 | 现在要找哪一单、哪一单要先处理 | 搜索、筛选、4–6 个扫描列、主状态、下一步、分页 | 完整明细、大段说明、所有技术字段 |
| 详情 | 当前单据是什么、卡在哪里、下一步做什么 | 标识、关键事实、主动作、业务分区、关联单据、附件和日志 | 可编辑外观的只读输入框、重复摘要、跨域越权操作 |
| 新建/编辑 | 完成一次准确录入 | 仅录入字段、即时校验、引用选择、保存/提交 | 尚不存在的流程节点、历史日志、结果摘要 |
| 规则/主数据 | 维护长期有效的业务规则 | 版本、适用范围、结构化规则、启停状态 | 伪造业务审批流和现场执行状态 |
| 工作台 | 高频判断与执行 | 当前班次/角色、待办、阻断、少而强的动作入口 | 普通单据列表模板、低频维护字段 |
| 报表 | 解释结果并下钻来源 | 指标、口径、筛选、趋势/对比、源单下钻 | 保存、审批、过账等业务动作 |

## 3. 页面信息层级

所有页面按相同阅读顺序组织：

1. **我在哪里**：模块、页面标题、单号或对象名称。
2. **现在什么情况**：主状态、关键进度、风险或阻断。
3. **我现在该做什么**：唯一主动作及明确下一步。
4. **我凭什么判断**：数量、来源、承接、库存、质检、交付等业务事实。
5. **发生过什么**：关联单据、附件、日志和审计记录。

右侧摘要只保留判断性信息，不重复主内容中已经清楚展示的字段。

界面质感重点依靠信息层级、留白、字体节奏、对齐、边框和交互反馈。避免用大面积色块、渐变、堆叠卡片和过量阴影制造“高级感”。

状态展示必须遵循事实拆分：主状态只表达对象自身生命周期；库存、质检、供应、履约、财务和异常分别展示，不合并为一个可编辑的综合状态。

## 4. 桌面布局基线

- 1186px 及以上：列表优先显示 4–6 个判断列并固定状态/下一步；不依赖横向滚动完成主要判断。
- 900–1185px：合并身份与来源等相邻字段，保留数量、阻断、状态和下一步；低频字段进入详情。
- 760px 以下：列表转业务卡片；主操作、状态、数量和风险保持可见，触控目标不少于 40px。
- 详情页桌面使用“主内容 + 280–320px 摘要”；中等宽度下摘要并入主内容顶部，不让只读表单占满首屏。
- 只读事实使用文本、事实网格或小型表格；只有真实可编辑字段才使用输入框外观。

## 5. 列表设计规则

- 一列只回答一个业务问题，列名使用业务语言。
- 第一列稳定显示单号/名称及一条身份摘要。
- 中间列优先显示数量承接、进度和阻断，不显示维护时间等低频信息。
- 状态列固定显示“主状态 + 下一步”，但按钮和路由不得依赖中文下一步文案判断。
- 行高默认 64–76px；同一单元格最多一个主值和两条短摘要。
- 搜索占主要宽度，排序/筛选/导出保持次级；新建是页面级主动作。
- 列表上方只允许一条职责/风险摘要，不堆装饰型统计卡。

## 6. 详情设计规则

- 标题区：返回、标题/对象、打印、PDF、日志、更多、唯一主动作。
- 首个内容区必须是“业务判断”，而不是大面积只读基础字段。
- 基础字段压缩为事实网格；备注为空时不占大块文本区域。
- 明细按业务顺序组织，优先显示来源与承接，再显示资源准备和下游执行。
- 关联单据以可下钻列表展示，禁止把多个流程对象合并为一个综合状态。
- 新建/编辑与只读详情使用不同布局，不用 `readonly input` 冒充详情文本。

## 7. 生产任务页面规格（历史草案，当前暂停）

本节保留 2026-07-15 已形成的生产任务页面思路，供后续生产阶段重新评审。它不是当前实施入口，也不代表页面已经由用户确认或冻结。

### 7.1 页面职责

生产任务是计划需求，不是现场执行单。页面只回答：

- 需求从哪里来、由谁负责、何时要完成；
- 要生产哪些成品、数量多少；
- 已经由多少工单承接、还有多少待建；
- 物料是否齐套、缺口有没有进入备料申请；
- 下一步是建工单、查看工单还是等待入库完成。

开工、报工、质检和入库不在生产任务页直接操作。

### 7.2 列表内容

固定为四个业务列和一个状态列：

| 列 | 主值 | 摘要 |
| --- | --- | --- |
| 任务/来源 | 任务编号 | 优先级、来源单据、负责人 |
| 生产需求 | 总需求数量 | 成品摘要、交期 |
| 工单承接 | 工单数/已计划 | 已释放、已入库、待建数量 |
| 物料准备 | 齐套/缺料结论 | 缺料项数、备料申请数 |
| 任务状态 | 计划承接状态 | 下一步 |

列表上方显示“总任务、待建工单、缺料任务、加急未完成”四个紧凑判断数，并提供生产工作台入口。

### 7.3 详情内容顺序

1. **任务判断**：需求、已建工单、待建工单、已入库、物料准备和下一步。
2. **任务来源**：编号、来源、负责人、优先级、创建时间、交期和非空备注。
3. **成品需求**：逐来源行显示计划、工单承接、入库和剩余。
4. **物料准备**：预计用量、净可用、缺口、待检/待入库/在途、预留/分配、备料申请。
5. **关联工单**：计划/释放、报工/入库、当前节点和交期。
6. **附件与日志**：只用于追溯。

主动作只允许“建工单”或进入已有工单继续跟踪。

## 9. 后续前端顺序

当前不继续从生产页面向下推进。新的模块顺序为：

1. 基础资料；
2. 销售；
3. 采购；
4. 仓库；
5. 财务；
6. 生产与质检；
7. 电商；
8. 首页、报表和系统完善。

每个模块先完成流程和页面规格，再提交浏览器原型验收。用户确认并标记交互冻结后，才进入必要底层联动。
