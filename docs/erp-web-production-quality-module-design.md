# Filatrix ERP Web 生产与质检联合设计

> 本文用于冻结生产、质检模块的流程边界、页面职责和状态口径。发生冲突时，以 `erp-web-prototype-blueprint.md` 和 `erp-web-business-fact-model.md` 为准。

## 1. 设计目标

生产模块负责把已确认的补货需求转成可计划、可释放、可执行和可追溯的生产事实；质检模块负责对来料、开机、过程、成品和入库前批次作出独立质量判定，并记录后续处置。生产不代替质检放行，质检不代替生产报工，二者都不代替仓库过账。

页面优先解决四个问题：

- 让计划员清楚知道“生产什么、何时交、物料是否具备、下一步做什么”；
- 让车间只处理已经释放到现场的数量，不直接改生产计划；
- 让质量结论、处置和库存效果分开表达，不再塞进一个主状态；
- 让管理者在工作台看到真实任务、工单、现场批次、质检和异常，不维护另一套演示数据。

## 2. 联合业务流程

```mermaid
flowchart LR
  A["销售缺口 / 备货需求"] --> B["生产任务"]
  B --> C["物料核对与备料申请"]
  B --> D["生产工单"]
  C --> E["仓库备料 / 采购补料"]
  D --> F["释放批次 RB"]
  E --> F
  F --> G["仓库发料"]
  G --> H["流转批次 EC"]
  H --> I["开机与生产报工"]
  I --> J["生产质检"]
  J -->|"合格或授权让步"| K["包装与待入库"]
  J -->|"不合格"| L["返工 / 降级 / 隔离 / 报废 / 复检"]
  L --> J
  K --> M["仓库完工入库"]
  M --> N["回写工单、任务与销售补货进度"]
```

来料侧流程独立存在：

`采购收货 → 质检冻结 → 来料检验 → 质量判定 → 业务处置 → 仓库正式入库或退货/隔离`

## 3. 核心对象边界

| 对象 | 唯一职责 | 不承担的职责 |
| --- | --- | --- |
| 生产任务 PT | 汇总生产需求、成品明细、交期、物料准备和工单承接 | 现场开工、报工、质检、入库 |
| 备料申请 PMR | 把生产缺口交给仓库判断，库存不足部分再承接采购 | 直接生成库存、直接批准采购 |
| 生产工单 MO | 冻结成品、数量、配方、工艺、计划日期和责任人 | 直接表示每个现场批次正在做什么 |
| 释放批次 RB | 表示工单中本次被允许进入现场的数量、产线、班次和负责人 | 代替现场执行记录或质量结论 |
| 流转批次 EC | 承载实际领料、开机、报工、包装、交接和异常 | 修改工单计划、作出质量放行、增加库存 |
| 质量任务 QC | 按标准记录抽样、检查项和质量判定 | 代替生产报工或仓库过账 |
| 质量处置 | 记录不合格数量如何返工、降级、隔离、退货、报废或复检 | 把处置动作混入质量结论 |
| 仓库单据 | 完成发料和正式入库并形成库存事实 | 倒推伪造生产或质量记录 |

## 4. 状态与事实拆分

### 4.1 生产任务

- 任务生命周期：待建工单 / 部分建单 / 已建单 / 已完成 / 已关闭；
- 物料准备：未核对 / 有缺口 / 补料中 / 已齐套；
- 工单承接：计划数量、已建单、未建单；
- 交付风险：正常 / 临期 / 逾期 / 阻断；
- “下一步”由以上事实推导，不保存成可编辑主状态。

### 4.2 生产工单

- 工单生命周期：草稿 / 已确认 / 执行中 / 已完成 / 已关闭；
- 释放进度：未释放 / 部分释放 / 已释放；
- 物料准备：未备料 / 备料中 / 已齐套 / 有缺口；
- 执行进度：未开工 / 生产中 / 部分报工 / 已报工；
- 质量进度：未触发 / 待检 / 检验中 / 有不合格 / 已放行；
- 入库进度：未报工 / 待入库 / 部分入库 / 已入库。

### 4.3 释放批次

释放批次固定并列展示五条事实线：

| 维度 | 示例 |
| --- | --- |
| 释放状态 | 待释放 / 已释放 / 已撤回 |
| 物料状态 | 待备料 / 待发料 / 已发料 / 有缺料 |
| 执行状态 | 待开工 / 生产中 / 已暂停 / 已报工 / 已结束 |
| 质量状态 | 未触发 / 待检 / 检验中 / 待复判 / 已放行 / 已拒收 |
| 入库状态 | 未报工 / 待入库 / 部分入库 / 已入库 |

页面可以给出一个醒目的“当前关注”或“下一步”，但它只能是推导结果，不能替代五条事实。

### 4.4 质量任务

- 任务生命周期：待检验 / 检验中 / 已判定 / 已关闭；
- 检验结论：待判定 / 合格 / 不合格 / 部分合格；
- 处置方式：待处置 / 放行 / 让步放行 / 返工 / 降级 / 隔离 / 退货 / 报废 / 复检；
- 处置进度：未开始 / 处理中 / 已完成；
- 库存效果：质检冻结 / 待仓库入库 / 已入库 / 已退货，不由质检页面直接写库存。

数量必须满足：`检验批数量 = 合格数量 + 不合格数量 + 待判定数量`。部分判定后，未判定数量继续冻结。

## 5. 页面清单与职责

### 5.1 生产模块

| 页面 | 首屏必须回答的问题 | 核心内容 |
| --- | --- | --- |
| 生产工作台 | 今天哪条线、哪个批次、哪项质量或异常最需要处理 | 今日计划、产线负荷、缺料、待检、异常、现场队列 |
| 生产任务 | 哪些需求还没被工单承接，是否缺料、是否影响交期 | 来源、成品需求、工单承接、物料准备、交付风险、下一步 |
| 备料申请 | 哪些缺口由仓库解决，哪些需要转采购 | 来源任务、物料、需求、可用、缺口、仓库受理、采购承接 |
| 生产工单 | 计划是否可释放，已经释放和完成多少 | 配方/工艺快照、计划量、释放量、物料、执行、质量、入库 |
| 流转批次 | 现场批次当前正在做什么，卡在哪条事实线 | 来源工单、产线班次、五维状态、报工数量、异常和下一步 |
| 损耗台账 | 哪些损耗异常、来源和责任是否清楚 | 工单/批次、物料、标准损耗、实际损耗、差异、原因 |
| 物料配方 | 成品单位产出需要哪些物料和标准损耗 | 成品、版本、物料用量、损耗、来料质检要求 |
| 工艺模板 | 该产品族按什么顺序和控制点生产 | 版本、适用产线、工序节点、参数与放行规则 |
| 工序节点 | 一道工序由谁做、何时完成、异常怎么办 | 作业内容、完成条件、责任角色、质量门、异常规则 |
| 异常闭环 | 哪些异常未解决，影响哪个任务、工单或批次 | 来源、分类、影响、责任人、措施、验证和关闭 |

### 5.2 质检模块

| 页面 | 首屏必须回答的问题 | 核心内容 |
| --- | --- | --- |
| 来料质检 | 哪批来料仍冻结，何时必须完成，结论和处置到哪一步 | 收货来源、物料批次、待判定数量、结论、处置、库存效果 |
| 生产质检 | 哪个现场批次在等质量决策，是否阻断生产或入库 | 质检类型、工单/批次、产线班次、结论、处置、下一步 |
| 质量巡检 | 哪条产线有哪些过程风险和待跟进问题 | 巡检计划、产线、检查项、问题、责任人、整改期限 |
| 质检标准 | 当前检验按哪个版本、哪些项目和什么抽样规则 | 类型、适用对象、版本、抽样规则、检查项、启停状态 |
| 不良记录 | 不良事实、数量、责任和处置是否闭环 | 来源质检、缺陷分类、数量、责任、处置、复检与关闭 |

## 6. 页面布局规范

- 列表页的新建和主要动作放在全局顶部栏，内容区不重复页面标题；
- 列表默认保留 4～6 组判断信息，不把附件、完整备注和操作菜单当判断列；
- 详情页顶部先显示“当前判断 + 下一步 + 阻断原因”，再显示稳定业务事实；
- 只读详情使用文本事实格、进度带、数量摘要和关联单据卡，不用禁用输入框伪装详情；
- 右侧摘要只保留有决策价值的风险、数量和关联，不重复主区已有整套基本信息；
- 编辑页只显示可编辑字段；系统编号、来源快照和累计量使用只读事实块；
- 所有页面统一使用顶部栏返回、主要动作、刷新和通知；正文不再放第二套返回和标题工具区；
- 页面文案只说明业务判断和操作结果，不出现“API、命令、原型映射、真实接口”等实现术语。

## 7. Filatrix 耗材测试场景

本模块只保留 3D 打印耗材及其原辅料场景，首轮覆盖：

1. `PLA 1.75mm 哑光黑耗材 1kg`：销售缺口触发生产，原料齐套，分两条挤出线释放，其中一批待入库抽检；
2. `PETG 1.75mm 透明耗材 1kg`：工单已确认但 PETG 原生粒子仍在来料复判，只允许计划、不允许释放；
3. `PLA 1.75mm 珍珠白耗材 1kg`：现场已报工，绕线问题部分不合格，进入返工和复检；
4. 原辅料包含 PLA/PETG 原生粒子、黑色/白色色母、线盘、真空袋、干燥剂、标签和纸箱；
5. 所有数量使用物料基础单位，不维护销售单位、采购单位或折合换算。

## 8. 实施顺序

1. 上游计划层：生产任务、备料申请、生产工单，先统一耗材数据、状态维度和详情布局；
2. 质量门：来料质检、生产质检、不良记录，拆分任务、结论、处置和库存效果；
3. 现场执行层：释放批次、流转批次和生产工作台，使用同一套事实聚合；
4. 规则与分析层：配方、工艺模板、工序节点、损耗台账、异常闭环；
5. 完成生产、质检、仓库和销售补货的跨模块回归。

## 9. 当前页面审计结论

- 生产任务和工单的列表结构已有基础，但测试数据仍混有电子模块和边界验收数据；
- 工单与流转批次详情大量使用只读输入框，主区与右侧摘要重复；
- 流转批次用“待质检、待仓库、待处理”等单一状态覆盖执行、质量和入库事实；
- 来料质检和生产质检列表把附件作为判断列，状态列又混合任务、结论与处置；
- 工作台概念正确，但信息密度过高、层级偏散，并出现接口或命令实现文案；
- 第一批先改生产任务和生产工单，冻结上游口径后再重构质检和现场工作台。

- `SO-20260715-022/L1` 的 300 卷 PETG 透明耗材由 120 卷库存预留和 `PT2-260715-006` 的 180 卷生产任务共同承接；
- PLA 哑光黑工单改为安全库存补货来源，不再错误占用上述销售订单；
- 珍珠白补料申请改为跟踪 `PR-20260716-003`，缺料只阻断释放和开工，不阻止建立计划工单；
- 报工量、合格量和不良量按守恒关系重新计算，报工全检存在不合格数量时必须先进入异常处置；
- 生产工作台只保留真实建单缺口与阻断批次；质检新增质量工作台，统一显示来料、生产、整改、不良和库存冻结待办；
- 来料质检和生产质检改为上游来源触发，人工新建仅保留质量巡检和不良记录；
- 完整审计矩阵见 `erp-web-seven-module-business-audit.md`。
