# Filatrix ERP Web 销售模块设计

> 本文是销售模块进入页面优化前的实施设计。发生冲突时，以 `erp-web-prototype-blueprint.md` 和 `erp-web-business-fact-model.md` 为准。

## 1. 模块目标

销售模块负责把客户需求转成可履约、可追踪的销售责任，不代替仓库执行出库，也不代替财务开票和收款。

主流程：

```mermaid
flowchart LR
  A["客户需求"] --> B["报价单"]
  B -->|"客户接受且报价有效"| C["销售订单"]
  C --> D["库存试算与预留"]
  D -->|"库存充足"| E["交付追踪"]
  D -->|"库存不足"| F["生产补货"]
  F --> E
  E --> G["仓库销售出库"]
  G --> H["客户签收"]
  H --> I["销售开票与应收"]
  I --> J["收款核销"]
```

## 2. 页面职责

| 页面 | 唯一职责 | 允许操作 | 不承担的职责 |
| --- | --- | --- | --- |
| 报价单 | 形成客户价格提案和商务条件 | 新建、保存、确认、变更、作废、转订单 | 库存承诺、生产安排、发货执行、开票收款 |
| 销售订单 | 形成正式履约责任并汇总履约事实 | 新建、确认、变更、关闭、作废 | 仓库出库操作、财务记账操作 |
| 交付追踪 | 从销售视角查看可发、待发、已发和签收 | 查看、补充销售侧交付要求 | 代替仓库销售出库单 |
| 销售售后 | 登记签收后的退换补、返工、折让和反馈 | 新建、处理、关闭 | 直接改写原订单和原出库记录 |
| 销售价格记录 | 查询已成交价格 | 搜索、筛选、导出 | 人工维护另一套价格真相 |
| 成品库存速查 | 给销售提供可承诺数量参考 | 搜索、筛选、跳转库存事实 | 直接改库存、直接锁库 |

## 3. 状态模型

### 3.1 报价单

主状态只表达报价生命周期：`草稿 / 已确认 / 已转订单 / 已作废`。

有效期是独立判断，不写入主状态：

- 有效：当前日期不晚于有效期，可以转订单；
- 临期：两天内到期，列表提示；
- 过期：保留“已确认”生命周期事实，但禁止直接转订单，必须先变更有效期；
- 已转订单、已作废：不再显示有效期风险动作。

### 3.2 销售订单

订单主状态最终只保留：`草稿 / 已确认 / 已关闭 / 已作废`。

以下内容必须作为并列事实展示，不能继续塞进主状态：

- 生产：无需生产 / 待生产 / 生产中 / 已完工；
- 交付：未发货 / 部分发货 / 已发货 / 已签收；
- 开票：未开票 / 部分开票 / 已开票；
- 收款：未收款 / 部分收款 / 已收款；
- 异常：正常 / 临期 / 逾期 / 阻塞。

## 4. 页面内容与布局

### 4.1 列表页共性

- 顶部栏承载新建动作，内容区不重复页面标题；
- 默认只展示 4–6 组决策信息；
- 主状态、履约进度、财务进度分栏呈现；
- 列表行只放摘要，详细历史和完整条款进入详情；
- 1186px 以上不依赖页面级横向滚动。

### 4.2 报价单列表

保留六组信息：单号、客户、销售物料、金额与商务摘要、报价与有效期、附件；右侧独立显示生命周期状态和下一步。

商务摘要必须来自真实已保存字段，不能用页面默认值伪造；过期报价的下一步显示“更新有效期”，不得显示“转销售订单”。

### 4.3 报价单详情

主区按判断顺序组织：

1. 报价身份：单号、公司、客户、联系人、报价日期、有效期；
2. 销售物料：图片、物料、数量、单价、金额；
3. 金额汇总：未税金额、税额、含税总计；
4. 商务条款：交付、运费、付款、计价、税率和补充说明。

右侧只保留三类有判断价值的信息：报价状态与有效性、最近成交价参考、附件。详情不使用禁用输入框伪装只读信息，也不重复展示一套流程节点。

### 4.4 报价单新建/编辑

- 只显示可编辑字段、只读报价人和即时金额计算；报价人由新建时的当前登录账号确定，普通编辑不允许更换；
- 公司默认当前主体但允许选择；
- 客户选择后带出联系人、电话和默认商务条件；
- 物料候选只允许选择启用且具备销售用途的物料，查询使用业务枚举“销售”而不是页面显示名“销售物料”；
- 确认前校验客户、联系方式、全部物料行完整且不重复、有效期和商务条件；
- 已过期的有效期不能确认。

### 4.5 销售订单详情

采用“订单责任 + 四条进度线”的详情结构：主区展示客户、物料、数量、交期、商务责任和内部发货要求；摘要区分别展示生产、交付、开票、收款以及异常。不得用“生产中、待开票、待收款”等履约状态替换订单主状态。

逾期、临期和暂停属于独立关注事实。服务端根据计划发货日、承诺交付日和实际出库/签收事实计算，订单详情和交付追踪必须使用同一口径。

### 4.6 交付追踪

- 销售订单确认后形成追踪记录，来源订单、收货要求和销售物料保持可追溯；
- 当前订单已锁定的库存仍可用于该订单的“可发判断”，不能当成别的订单占用而重复判缺；
- 页面同时显示计划、累计已发、剩余待发、现货缺口和补充后缺口；
- 计划发货或承诺交付逾期时，顶部待办优先提示逾期，不被“待发货”主状态覆盖。

### 4.7 销售售后

销售售后是独立持久化单据，不再根据销售订单临时伪造。状态为 `待受理 / 处理中 / 待确认 / 已关闭`，每次登记、变更和推进均写入日志；来源订单只作为事实引用，售后处理不得反向覆盖原订单。

### 4.8 成交价与库存速查

- 报价、订单、成交价和库存速查统一使用物料基础单位，不维护默认销售单位或“每箱折合”；装箱要求由包装物料、包装规则或单据备注表达；
- 成交价从非草稿、非作废销售订单明细实时沉淀，并保留来源订单；
- 库存“当前可用”已经扣除了预留、分配和冻结，销售侧可承诺量只再扣除尚未计入可用的出库占用，禁止重复扣减锁定量；
- 待入库和在途数量只用于“补充后可承诺”参考，不计入当前现货承诺。

## 5. 动作层级

- 一级动作：当前页面最关键的下一步，例如确认报价、转订单、确认订单；
- 二级动作：保存、编辑/变更、打印、日志；
- 低频动作：作废、关闭等进入“更多”；
- 禁止动作必须同时在前端和服务端拦截，并给出明确原因；
- 已过期报价的主动作改为“更新有效期”，完成变更后才允许转订单。

## 6. 实施顺序

1. 报价单：统一列表顶栏、修复真实条款数据、重做详情只读布局、增加有效期规则；
2. 销售订单：拆分主状态与生产/交付/开票/收款事实；
3. 交付追踪：收敛为销售侧只读履约视图；
4. 销售售后：明确来源、责任、处理动作和金额影响；
5. 销售价格记录与成品库存速查：完成只读查询页收敛；
6. 完成销售模块全量浏览器回归和跨模块联动校验。
