# Filatrix ERP Web 销售与采购原型收口清单

更新时间：2026-07-28

本清单只跟踪销售、采购、采购入库、售后协同及其页面体系的当前原型结论。业务权威仍以 `erp-web-prototype-blueprint.md` 和 `erp-web-business-fact-model.md` 为准；历史章节与旧设计文档出现冲突时，以两份权威文档最后追加的现行合同为准。

| 收口项 | 当前结论 | 状态 | 验收证据 |
| --- | --- | --- | --- |
| 独立财务模块 | 当前路由、菜单和生产构建不再提供财务模块；财务 API 统一返回 410。销售只登记开票/回款，采购只登记收票/付款。 | 已完成 | `build`、`smoke:frontend`、`audit:ui` |
| 售后财务执行任务 | 售后只向仓库、质检、生产生成物理执行任务；销售/采购自行确认金额结果，不再创建财务待办、结算入口或财务确认金额锁。 | 已完成 | `smoke:after-sales`、售后执行页静态排除门禁 |
| 采购超收 | 订单确认时冻结 5% 自动超收容差。累计接收与异常暂收在容差内可登记，超过容差的到场实物必须拒收或进入异常处理。 | 已完成 | `smoke:purchase` 同时覆盖 5,001/5,000 允许与 5,251/5,000 拒绝 |
| 采购短收 | 短收后默认继续生成待收货任务；采购可执行“关闭待收余量”，逐行保存关闭数量、原因、时间和经办人，并取消未开始的仓库任务。 | 已完成 | `smoke:purchase` 覆盖部分到货、关闭余量、任务取消和进度完成 |
| 角色边界 | 仓库登记到场/接收/拒收/异常暂收并执行正式入库；采购决定供应商是否补交及是否关闭余量；质量作技术判定。仓库页面不提供跨模块代办动作。 | 已完成 | 权限门禁、采购入库页、采购关闭余量命令 |
| 数量与入库 | 到货、质检、可入库、已入库、拒收和关闭余量为独立数量事实；允许部分入库和分仓入库，批次管理物料在首次正式入库时自动生成批次。 | 已完成 | `smoke:warehouse`、`smoke:flow` |
| 销售/采购跟进页面 | 左侧承载业务过程，右侧承载进度与关联记录；商务记录按开票/回款、收票/付款拆组并使用紧凑记录。 | 已完成 | `build`、`audit:ui`、浏览器验收 |
| 页面骨架 | 订单、跟进、售后和仓库执行页复用系统级顶部、正文卡片、右侧摘要、状态和对话框语言；新增关闭余量使用已有业务对话框视觉体系。 | 已完成 | `audit:ui`、桌面浏览器验收 |
| 数据库准备 | 当前仍是 JSON 原型；命令、幂等键、逐行来源键、关闭事实和状态投影已按未来数据库实体设计。数据库选型和迁移不在本轮原型收口范围。 | 已明确后续 | 两份权威业务文档的数据合同 |

## 本轮验收结果

- 自动门禁：生产构建、159 项 UI 一致性审计、前端、销售、采购、轻量商务记录、仓库、售后和完整业务流烟测全部通过。
- 浏览器验收：采购跟进页可正确显示 5% 容差、容差内超收和分行到货/入库进度；销售跟进页与采购跟进页使用同一骨架；采购售后单据不再出现财务任务、售后结算或财务确认金额。
- 当前阶段结论：销售、采购和采购入库的原型规则已经形成可测试的业务合同；进入数据库阶段时应把命令、行级关闭事件、到货、质检和入库过账拆为独立实体。

## 非阻断历史债务

- `src/views/Finance*` 与服务端部分财务函数仍作为未路由、未打包的历史兼容代码存在，不能被当前用户访问。进入数据库实现阶段时，应先导出历史演示数据，再物理删除这些兼容文件和不可达分支。
- 旧文档中“财务执行任务”“禁止任何超收”“采购收货确认时生成批次”等表述属于历史方案，不应再作为新页面、接口或测试依据。
- 原型确定后需要数据库；届时应把 `PurchaseReceiptClosure`、`CommercialFollowUpEvent`、到货结果、质检判定和入库过账设计为独立持久化事实，而不是继续扩展单个 JSON 单据状态。
