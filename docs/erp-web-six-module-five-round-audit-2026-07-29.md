# Filatrix ERP Web 六模块多轮审计与优化记录

日期：2026-07-29  
范围：基础资料、销售、采购、仓库、生产、质检  
结论：完成十二轮检查、优化和真实回归；本轮不扩展新的业务域。

## 1. 审计目标

- 字段表达业务事实，不把生命周期、阶段进度、质量结论和商务进度混为一个状态。
- 页面沿用同一骨架：标题/面包屑、单一工具栏、正文、状态与关联记录、分页。
- 列表状态使用同一种视觉语言；只有存在真实分子/分母时才显示进度条。
- 角色只执行本模块动作，跨模块只读查看交接结果和来源编码。
- 桌面、平板和移动端使用同源数据，不以隐藏关键字段换取窄屏适配。

## 2. 十二轮结果

### 第一轮：页面与字段基线

- 盘点 50 个一级页面入口：基础资料 11、销售 5、采购 5、仓库 11、生产 11、质检 7。
- 六模块全部列表、新建页和代表详情均能加载，未发现路由空页或控制台业务错误。
- 基础资料继续定位为引用事实维护，不增加审批轨道或伪工作流。
- 物料列表重新分配列宽，质检属性和保质期不再被压缩为难读窄列。

### 第二轮：基础资料、销售、采购

- 复核物料、客户、供应商、报价、销售订单、采购申请、物料采购、资产采购的字段分组和只读边界。
- 销售和采购跟进继续把开票/收票、回款/付款拆成两个独立记录组，只填写金额、日期、备注。
- 新增轻量商务记录成功后登记表单自动收起；失败时保留输入，避免重复点击或误以为没有保存。
- 商务记录删除改为系统内确认对话框，不再使用浏览器原生确认框；确认后累计金额、阶段进度和关联记录同步重算。

### 第三轮：仓库、生产、质检闭环

- 采购入库、调拨、盘点、生产领退料、完工入库、生产任务/工单/执行、来料/生产/出货质检均通过专项回归。
- 采购入库维持“采购订单生成待收货任务 → 仓库到货确认/拒收 → 按物料属性质检 → 分批分仓正式入库”的闭环。
- 调拨库位为仓库内候选选择，不允许自由填写；批次、质检和保质期使用物料属性快照驱动。
- 仓库、生产、质检不通过跨模块按钮代替目标角色执行，只显示来源和交接结果。

### 第四轮：状态列与视觉统一

- 新增共用 `ListStatusOverview`，仓库、生产、质检列表统一使用“主状态、关注项、阶段事实、下一步”的紧凑结构。
- 主状态统一调用 `statusPresentationClass`，颜色语义固定为中性、执行中、完成、提醒、异常。
- 只有生产任务/工单/执行存在真实计划量与入库量时显示进度条；质量结论和仓库阶段不伪造成百分比。
- 列表行高、状态列宽和移动卡片信息顺序统一，避免同一系统中每张列表各画一套状态组件。

### 第五轮：真实操作与角色边界

- 真实创建、保存并提交仓库调拨 `TR-20260729-001`，验证调出仓、调入仓、调入库位、原因和明细保存。
- 真实登记销售回款并删除测试记录，验证金额、日期、备注、自动收起、删除确认、累计金额和关联记录重算。
- 仓库账号越权采购、采购账号越权质检、生产账号越权质检、质检账号越权生产均被路由和权限守卫拦截；侧栏只显示本角色模块。
- 成功保存、提交和登记后不再误触发未保存提醒；未保存编辑仍由离开保护拦截。

### 第六轮：响应式与最终门禁

- 在 390px、900px、1280px 三个宽度实测六模块代表列表，所有页面 `scrollWidth = innerWidth`，无整页横向溢出。
- 390px 下列表切换为同源卡片，状态、数量、风险和下一步仍保留；900px 使用宽卡片，1280px 恢复桌面表格。
- 生产列表的真实数量进度条在移动端仍具备 `progressbar` 语义；仓库和质检状态不出现虚假进度条。

### 第七轮：仓库角色状态、排序与页面语义

- 复验采购入库整单拒收样本 `WR-20260728-001`：当拒收量大于零、正常接收量和异常暂收量均为零时，质检投影固定为“未送检”，不再由物料“需质检”属性误推为“待处理”。
- 仓库列表主状态改为当前角色视角：整单拒收显示“已拒收”，待质检和异常暂收显示“等待协同”；下一步仍明确由采购或质量继续处理。
- 实测“日期从旧到新”发现未知日期曾被排在有效日期之前；统一日期比较后，`-`、`—` 和空日期在升序、降序及状态内次序中均放到末尾。
- 修正生产工作台和售后执行任务中的嵌套 `<main>`，业务页只保留应用级主内容区，内部区域使用 `section` 或普通布局容器。
- 六模块代表列表再次实测搜索无结果、清空条件；采购入库追加实测排序、拒收详情和待质检协同状态。

### 第八轮：生产可安排量、异步稳定态与质检滞留

- 生产任务 `PT2-260715-006` 虽然仍有物料待检和待入库，但已有 `161卷` 可安排。下一步由错误的整单等待改为“先安排 161卷，余量待物料”，列表与详情读取同一事实。
- 任务动作优先级调整为先建工单、再安排现有产能、再跟踪执行、最后解释剩余物料阻断。`PT2-260701-003` 的主按钮与“继续创建剩余工单”一致，实测进入新工单并预填待建 `232卷`。
- 生产库存投影和来料质检实时收货投影加载前改为显式加载态，避免旧样本或空投影先渲染、异步完成后再静默改变下一步。
- 来料质检“状态优先”补齐未进入处置的阶段权重，执行中待办按任务日期从旧到新排在已完成任务之前。
- 未关闭来料质检按自身任务日期显示“滞留 N 天”，统一使用异常关注色；不再把采购预计到货日期误当质量截止日期。

### 第九轮：仓库引用、生产加载与质量时限

- 再次逐页复核六模块 50 个一级入口及代表性新建、详情、跟进、执行页；页面骨架和状态视觉保持统一，未发现空页或整页横向溢出。
- 采购收货的缺失预计日期显示“未登记”；仓库售后作业库位由仓库主数据提供候选并阻止自由输入。
- 历史仓库名称按仓库编码校正，确保 `WH-FG` 等编码在各类单据中使用同一个主数据名称。
- 生产工单列表响应聚合任务、备料申请、执行卡和下达批次，移除逐工单读取及重复详情加载。

- 再次实跑六模块 50 个一级入口和代表性新建、详情、跟进、执行页；未发现空页、长期加载、关键动作缺失或视觉骨架分叉。

### 第十一轮：动作真实性、未保存保护与确认框

- 检查方式从“逐页看正常态”升级为页面、状态、角色、操作结果四维矩阵，先用静态副作用扫描定位 `window.confirm`、临时状态覆盖和伪成功文案，再用浏览器验证取消/确认分支。
- 新增应用级统一确认框，替换销售、采购、基础资料、生产、质量页面的原生确认。确认框具备对话框语义、焦点管理、Esc/遮罩取消以及警告/危险色。
- 质检标准编辑页补上未保存保护；远端失败不再回退为内置样本可编辑页。浏览器实测取消离开保留输入，确认离开后返回列表。
- 来料质检和生产质检详情原“异常 / 作废”只修改前端状态，刷新即丢失且绕过数量处置链，现已删除；两类页面更多菜单均只保留真实变更。
- 质量判定、复检与处置继续调用服务端命令，页面日志改用响应中的完整流转记录；生产更多操作清除无法到达的“操作已记录”兜底。
- 隔离完整流程烟测通过，证明采购入库、质检判定/复检/退货、生产和质量闭环未因交互收敛而回归。

### 第十二轮：权限、终态、失败恢复与重复命令

- 使用仓库角色直达基础资料和销售订单，均由守卫退回首页并显示具体缺失权限；菜单与路由权限保持一致。
- 使用已关闭销售、采购样本访问 `/edit`，确认字段真实只读且没有保存/确认入口。采购终态标题修正为“物料采购只读”，不再与“已锁定”冲突。
- 逐一访问销售、采购、仓库、生产、质检和基础资料的不存在编码。生产原本只显示标题与返回按钮，现统一为对象说明、重试和返回骨架。
- 生产运行聚合失败不再以本地样本伪装正式数据；列表和详情显示明确加载失败，恢复后可重试读取运行数据、库存投影和当前详情。
- 静态扫描确认销售、采购和仓库核心编辑器具有函数级异步互斥；接口专项覆盖重复确认、重复提交、重复过账和幂等回放，浏览器确认框由当前执行者完成，不遗留悬空弹窗。

### 第十三轮：多 Agent 事实真实性、角色链接与并发

- 三个只读 Agent 分别检查基础资料/销售、采购/仓库、生产/质检；主线程复核后确认 10 项 P1、5 项 P2、1 项 P3。实施阶段按文件所有权拆分，先修数据完整性和角色边界，再处理共享异常骨架。
- 质检详情移除任意 URL 编码伪草稿；巡检/不良新建修复固定幂等键。来料、生产、巡检、不良和质检标准列表不再在接口失败时显示样例实时待办。
- 生产工作台首屏失败不再暴露可执行种子；生产任务和备料申请增加修订号及稳定幂等键，覆盖多标签保存、慢响应和网络重试。
- 采购部分入库按有效 posting 立即累计。仓库调拨、完工入库增加真实库位选择和服务端归属校验；库存流水和过账执行人固定使用认证人员。
- 基础资料新建加载期间锁定保存。资产来源失败页面已由主线程实际点击“改为手工建档”及系统确认，确认后正确移除来源参数并恢复保存。
- 通知跳转按接收角色校正：仓库进入 WR/WS 执行页，采购和销售进入订单跟进。系统日志不再把 SR 链到退役交付追踪页。

- 完整 API 回归进一步发现通知数组在目标账号/可见性归一化时会被替换，导致通知创建和已读更新写入旧引用；现已统一在归一化后重新定位当前数组/记录。调拨步骤烟测也补齐 `PKG-01` 真实目标库位，未削弱多库位必须选择的服务端规则。

## 5. 后续边界
