# Filatrix ERP Web 仓库模块设计

> 日期：2026-07-17  
> 定位：仓库模块的流程、页面和业务验收基线。若与历史优化清单冲突，以 `erp-web-prototype-blueprint.md`、`erp-web-business-fact-model.md` 和本文为准。

## 1. 模块目标

仓库模块只负责库存事实和现场作业，不替销售决定交付承诺、不替采购决定供应商履约、不替质检作判定、不替生产维护计划。

仓库需要稳定回答四个问题：

1. 当前有什么、在哪里、能不能用；
2. 哪些数量已经承诺给销售或生产；
3. 哪张作业单正在把库存从什么状态移动到什么状态；
4. 库存为什么发生变化，能否追溯到来源行、批次、库位和经办人。

## 2. 统一库存口径

库存查询统一展示以下数量，不再用一个“库存数”承担全部含义：

| 库存事实 | 回答的问题 |
| --- | --- |
| 物理在库 | 货是否已经在厂或仓内 |
| 合格在库 | 是否完成质量放行和仓库过账 |
| 可用 | 还能被新的销售、生产或调拨需求占用多少 |
| 销售预留 | 已承诺给销售订单但尚未出库多少 |
| 生产分配 | 已指定给释放批次但尚未领料多少 |
| 冻结 | 因盘点、异常或人工控制暂不可动用多少 |
| 待检 | 已到厂但尚未完成质检判定多少 |
| 待入库 | 已放行但尚未完成仓库入库过账多少 |
| 在途 | 采购或调拨已经发出、尚未到仓多少 |

统一计算：

```text
可用 = 合格在库 - 销售预留 - 生产分配 - 冻结
```

待检和待入库不属于合格在库，不能在可用公式中重复扣减。

## 3. 页面清单与职责

| 页面 | 类型 | 唯一职责 | 本阶段处理 |
| --- | --- | --- | --- |
| 库存查询 | 只读判断页 | 按物料、库位、批次查看库存事实与占用来源 | 重点优化 |
| 采购收货 | 作业单据 | 登记到货、质检冻结、放行待入库和正式入库 | 重点优化 |
| 销售出库 | 作业单据 | 承接销售交付、拣货、复核并消耗预留 | 重点优化 |
| 库存调拨 | 作业单据 | 调出、在途、到达和调入过账 | 重点优化 |
| 库存盘点 | 作业单据 | 形成盘点快照、冻结范围、录入实盘、复核差异并过账 | 重点优化 |
| 其他出入库 | 作业单据 | 处理样品、报废、借用归还等非主链库存变动 | 优化并限制用途 |
| 库存流水 | 只读追溯页 | 回答何时、为何、由谁改变了库存 | 优化 |
| 生产领料 | 作业单据 | 按工单释放和生产分配出库 | 保留真实链路，生产阶段深化 |
| 生产退料 | 作业单据 | 按原领料和可退数量退回 | 生产阶段深化 |
| 完工入库 | 作业单据 | 按生产质检放行额度入库 | 保留真实链路，生产阶段深化 |

批次追溯并入库存查询的“批次视角”和选中物料详情，不保留独立菜单。旧地址重定向到库存查询批次视角。

## 4. 核心流程

### 4.1 采购收货与入库

```text
草稿登记
  -> 确认到货
  -> 需要质检：质检冻结 -> 来料质检 -> 待入库
  -> 免检：直接进入待入库
  -> 仓库入库过账
  -> 合格在库与可用库存
```

规则：

- 来源采购行、收货数量、基础单位、批次、目标仓库和库位必须明确；
- 累计收货不得超过采购行剩余数量；
- 到货后来源、物料、数量、批次和质检规则锁定；
- 质检规则由物料和采购行带入，仓库不能改成免检；
- 质检放行只形成待入库，仓库过账后才形成合格和可用；
- 不合格数量留在隔离/退货/复检承接，不得随合格数量一起入库。

页面主判断拆成：收货生命周期、质检进度、入库进度和数量处置，不再只显示一个模糊主状态。

### 4.2 销售出库

```text
待受理 -> 待拣货 -> 待复核 -> 已出库
```

规则：

- 必须来源于有效销售订单或交付追踪行；
- 可出库额度按来源行剩余数量校验；
- 优先消耗当前销售订单的有效预留，再使用未预留可用库存；
- 出库过账同时扣减物理/合格在库、消耗预留并追加库存流水；
- 不能消耗其他订单的预留；
- 仓库显示“已出库”，销售侧根据交付事实显示“部分发货”或“待签收”。

### 4.3 库存调拨

```text
草稿 -> 待出库 -> 调拨中 -> 待入库 -> 已完成
```

规则：

- 调出仓确认出库时立即扣减调出仓库存并增加调入仓在途；
- “调拨中”和“待入库”期间不得仍把数量算作调出仓可用；
- 调入仓入库过账时减少在途并增加调入仓物理、合格和可用库存；
- 调出与调入分别形成库存流水；
- 批次和基础单位全程保持一致，不能在调拨过程中改物料或数量；
- 同一调拨动作不得重复扣减或重复入库。

### 4.4 库存盘点

```text
待盘点 -> 盘点中 -> 待复核 -> 已完成
```

规则：

- 开始盘点时按仓库和范围生成不可覆盖的库存快照明细；
- 盘点范围内尚未被销售预留或生产分配的可用数量进入盘点冻结；
- 盘点人员逐行录入实盘数量，系统计算差异；
- 提交复核前必须完成全部盘点明细；
- 完成盘点时按差异形成盘盈/盘亏流水并释放盘点冻结；
- 已完成盘点只读，原账面、实盘和差异必须可追溯。

### 4.5 其他出入库

第一版只允许明确用途：样品出库、领用出库、报废出库、借用出库、借用归还、库存调整。领用出库承接备件、工具或日常物品的部门/人员领用；生产领退料、采购收货、销售出库、调拨和盘点差异不能借“其他出入库”绕过主流程。

流程为：草稿 -> 待审核 -> 待过账 -> 已过账。提交和过账前校验用途、方向、仓库、物料、基础单位和数量。

## 5. 页面规格

### 5.1 作业列表

- 顶部新建按钮统一放公共顶部栏；
- 列表只保留单号/来源、对象、物料与数量、仓库/流向、日期、经办人、附件、主状态与下一步；
- 行点击进入详情，不增加操作列；
- 默认按待办优先排序，已完成靠后；
- 状态固定右侧，但业务判断不得依赖“下一步”中文文案。

### 5.2 作业详情

信息顺序：

1. 下一步与当前阻断；
2. 来源和作业事实；
3. 物料、批次、库位与数量；
4. 本单库存影响；
5. 关联单据、附件和日志。

详情页使用事实网格和文本，不用只读输入框冒充详情。右侧第一块为流程节点，其后只放库存影响、关联事实和附件，不重复主内容。

### 5.3 新建/编辑

- 只显示本次录入需要的字段；
- 物料、仓库、人员和来源单据使用可搜索引用选择器；
- 所有业务数量使用物料基础单位；
- 草稿可编辑，进入跨部门或库存移动后锁定关键字段；
- 保存与提交分别校验，不在刚进入页面时大面积报错；
- 新建/编辑页不显示未来流程摘要和悬浮参考。

### 5.4 库存查询

- 默认物料视角，一条物料主行展示汇总量，不要求用户手工汇总批次；
- 可切换库位视角和批次视角；
- 选中行详情展示九类库存事实、仓库分布、批次/库位、占用来源和最近流水；
- 库存查询和库存流水都是只读页，不放流程节点、附件上传和主操作；
- 批次来源和质量状态在库存查询详情中完成追溯。

### 5.5 库存流水

固定展示发生时间、物料、批次、仓库/库位、变动类型、变动数量、变动后余额、来源单据、原因和经办人。来源单据可下钻时必须提供入口。

## 6. 状态与权限边界

- 主状态只表达当前仓库单据生命周期；质检、预留、在途、差异和异常分别展示；
- 质检人员不能直接执行仓库入库过账；仓库人员不能改质检判定；
- 进入库存移动后的关键字段不能通过普通编辑覆盖；修正应使用更正、冲销或反向单据；
- 页面禁用只改善操作体感，服务端仍校验来源行、剩余数量、状态、版本、权限和幂等键。

## 7. 测试数据与验收场景

仓库测试数据至少覆盖：

1. 一张部分质检的采购收货；
2. 一张已完成采购入库；
3. 一张待拣货销售出库和一张已出库记录；
4. 一张待出库或调拨中的库存调拨；
5. 一张盘点中或待复核盘点；
6. 一张待审核其他出入库；
7. 库存查询中可见销售预留、生产分配、待检、待入库、冻结和在途；
8. 库存流水能解释采购入库、销售出库、生产领料、调拨和盘盈盘亏。

验收必须同时通过：业务专项烟测、前端烟测、UI 一致性审计、类型检查、生产构建和 1186px 桌面浏览器逐页检查。

## 8. 第二轮验收结论（2026-07-17）

- 生产领料、生产退料和完工入库不再提供脱离来源事实的独立新建入口；分别等待释放批次、退料申请和质检放行事实生成仓库任务；
- 其他出入库只保留样品出库、领用出库、报废出库、借用出库、借用归还和库存调整，库存方向由业务类型自动确定，只有库存调整允许选择方向；
- 调拨提交后锁定物料、数量和仓库，盘点开始后锁定仓库、范围、负责人和账面快照；盘点更新只接收逐行实盘数量；
- 盘点范围按库位、物料、批次或全仓口径由服务端匹配，未匹配到可盘库存时阻断开始盘点；
- 详情页的只读输入框已改为事实文本，右侧摘要改为库存影响，不再重复基本信息；
- 库存流水补齐采购到货质检冻结、质检放行、正式入库和销售出库测试事实，来源单据提供可下钻入口；
- 列表默认待办优先，生产链空状态说明真实触发条件，不再暗示用户手工补建业务事实。

## 9. 第三轮验收结论：不可变冲销事实（2026-07-17）

- 已完成的采购收货、销售出库、库存调拨、库存盘点和其他出入库不再只有“禁止编辑”的提示；有权限的用户可从“更多”发起库存冲销，并必须填写原因；
- 冲销不覆盖原单、不删除原库存流水，也不把原单生命周期状态改成“已冲销”。系统新增独立 `RV2` 冲销事实，原单仅保存冲销编号、原因、操作人和时间等关联证据；
- 冲销逐行生成与原流水方向相反的库存流水，并保存原单、原流水与可下钻来源。列表下一步和详情独立提示冲销结果，主状态继续只表达原单生命周期；
- 服务端校验单据已过账、未被冲销、库存仍足以反向移动和幂等键。相同幂等键重试返回同一结果，新请求不得对同一原单重复冲销；
- 销售出库冲销同时恢复本单已消耗的销售预留并重新聚合交付进度；采购收货冲销重新聚合采购入库进度；完成调拨必须成对冲回调出和调入流水；
- 已被下游占用或库存不足时阻断冲销，要求先解除占用或处理下游单据。采购收货中未入库的不合格、退货与差异数量仍由质检处置链承接，不能借库存冲销绕过；
- 生产领料、生产退料和完工入库具有释放批次、流转批次、质检与工单进度等专门关系，本轮不接入仓库通用冲销；后续在生产与质检模块中设计专用反向链，避免只改库存而破坏生产事实。
