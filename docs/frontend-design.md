# filatrix ERP 前端设计蓝图

## 1. 设计目标

filatrix ERP 是面向中文制造企业日常执行的网页端，不做营销首页，不复用旧 S-PMS 的前端壳层。第一屏就是角色工作台，优先服务销售、仓库、生产、质检等高频角色。

设计关键词：

- 中文业务语义优先：页面、按钮、字段使用国内企业容易理解的表达。
- 低噪音：少装饰、少解释文案，突出待办、单据、状态和操作。
- 单据友好：列表、详情、编辑、审批、扫码、批次追溯要形成统一模式。
- 多端适配：PC 完整处理，平板兼顾现场与管理，手机聚焦待办、扫码、审批和现场记录。
- 后端解耦：第一阶段使用 mock 数据，页面结构稳定后再接真实 API。

## 2. 信息架构

一级模块固定保留：

| 模块 | 首页定位 | 第一阶段状态 |
| --- | --- | --- |
| 首页 | 按权限聚合的业务待办数量、内部通知 | 优先完成 |
| 销售 | 报价单、销售订单、销售价格记录、成品库存速查 | 优先完成 |
| 采购 | 采购申请、物料采购、资产采购、采购单价 | 骨架入口 |
| 仓库 | 采购入库、销售出库、生产领料、生产退料、完工入库、调拨、盘点、库存查询、批次追溯 | 第二批 |
| 生产 | 生产任务、生产工单、生产领料、现场记录、配方、工艺、巡检 | 第二批 |
| 质检 | 来料质检、生产质检、质检模板、不良记录 | 第二批 |
| 财务 | 发票、收付款、应收应付、总账、利润表 | 后续 |
| 基础资料 | 公司、客户、供应商、物料、仓库、资产、单位、部门、员工 | 逐步补齐 |
| 报表 | 销售、采购、库存、生产、质检、财务报表 | 后续 |
| 系统 | 权限、角色、菜单、配置、编码规则、通知、应用、MCP、日志 | 保留入口 |

侧栏不放数字角标。需要提醒的信息进入首页待办或顶部通知。

信息架构建议：

- 侧栏按业务流顺序组织：首页、销售、采购、仓库、生产、质检、财务、基础资料、报表、系统。
- “基础资料”只放业务主数据，不放权限、菜单、日志等系统治理能力。
- “系统”只放平台配置和治理能力，例如权限、角色、菜单、编码规则、通知、应用、MCP 工具、日志。
- 客户、供应商、物料等主数据以“基础资料”为唯一维护入口，销售/采购页面可以提供快捷入口，但不要重复维护一套页面。
- 报表不抢占日常操作入口，先做各模块报表列表和筛选，再做图表、导出和经营分析。
- 首页不是模块入口集合，而是待办数量和内部通知入口。

## 3. 应用壳层

### PC

- 页面背景：暖灰 `#e8e8e2`。
- 主应用框：居中，浅色背景 `#f7f7f3`，轻边框和轻阴影。
- 左侧栏：深色 `#0f0f0f`，宽度 `168px - 184px`。
- 顶栏：高度 `48px - 52px`，左侧为“模块 / 页面”面包屑和当前任务上下文，右侧为页面操作、刷新、通知；不设置菜单型全局搜索。
- 用户信息只放侧栏底部，顶栏不放头像。

### 平板

- 侧栏可保持窄栏，也可根据宽度收起。
- 主区避免三栏布局，优先两栏或单栏。
- 单据详情可用右侧抽屉或页面内分区。
- 表格列数减少，低优先级字段进入详情。

### 手机

- 侧栏变抽屉。
- 顶栏保持单行紧凑布局：菜单、当前任务、主操作、刷新和通知按优先级收缩。
- 列表从表格变卡片。
- 不强行完整编辑复杂单据，手机优先支持：待办处理、扫码、审批、现场记录、库存速查。

## 4. 视觉规范

### 颜色

| 用途 | 建议值 |
| --- | --- |
| 页面背景 | `#e8e8e2` |
| 应用背景 | `#f7f7f3` |
| 面板背景 | `#fbfbf8` / `#ffffff` |
| 侧栏背景 | `#0f0f0f` |
| 侧栏 hover | `#1f1f1f` |
| 主文字 | `#22231f` |
| 次文字 | `#73736c` |
| 边框 | `#deded7` |
| 主操作 | 深绿色系，例如 `#3f674f` |
| 风险/异常 | 暗红系，例如 `#9b4a43` |
| 警示/待处理 | 暗琥珀系，例如 `#9b6931` |

不用大面积渐变、光斑、装饰性背景。卡片圆角控制在 `8px` 左右。

### 字体与密度

- 默认字体：系统中文字体栈，保持 `letter-spacing: 0`。
- 页面标题：`22px - 24px`。
- 面板标题：`16px`。
- 表格/列表正文：`13px - 14px`。
- 操作密度偏紧凑，适合后台反复使用。

### 图标

- 优先使用 `lucide-vue-next`。当前包有弃用提示，但已能稳定安装；后续确认新包版本后再迁移。
- 工具按钮使用图标按钮：刷新、通知、设置、搜索、扫码、编辑、删除。
- 常规业务动作可使用文字按钮：新建报价单、提交审核、确认入库。

## 5. 通用页面模板

### 工作台页

用于首页、仓库工作台、生产工作台等需要聚合待办和状态的入口页。

结构：

1. 页面标题 + 日期/关键筛选。
2. 统计卡片。
3. 主列表或待办列表。
4. 右侧或下方辅助信息，例如内部通知、异常提醒。

### 列表页

用于报价单、销售订单、物料采购、库存查询等。

结构：

1. 标题 + 主操作。
2. 筛选栏：关键字、状态、日期、客户/供应商。
3. 数据表格。
4. 分页。
5. 批量操作只在选中行后出现。

PC 使用表格；手机使用卡片列表。

### 单据详情页

用于销售订单、采购入库、生产工单等。

结构：

1. 顶部摘要：单号、状态、客户/供应商、金额/数量、负责人。
2. 操作条：提交、审核、撤回、打印、更多。
3. 主信息区：基础信息、明细、费用/金额、附件/备注。
4. 右侧或底部时间线：创建、审核、出入库、开票、收款等。

### 单据编辑页

结构：

1. 基础信息表单。
2. 明细表格，可新增/删除行。
3. 自动计算区域。
4. 保存草稿、提交审核。

规则：

- 字段分组要稳定。
- 必填项清晰。
- 错误提示就近显示。
- 不在同一屏塞过多低频字段，低频字段放“更多信息”。

### 扫码/现场页

用于仓库、生产现场、质检。

结构：

1. 大搜索/扫码输入。
2. 当前单据或工单摘要。
3. 大按钮操作。
4. 少字段、少跳转。
5. 异常入口固定可见。

手机和平板优先优化这类页面。

## 6. 首页设计

首页主标题：`待办看板`。

布局：

- 左侧主区：`待办看板`。
- 右侧窄区：`内部通知`。
- 待办按业务域聚合，只显示数量，不在首页展示具体单据明细。
- 用户拥有哪个业务角色或权限，就显示对应待办板块；拥有多个角色时显示多个板块。
- 管理员默认显示全部业务待办板块。

待办板块建议：

| 板块 | 可见权限/角色 | 小分类示例 |
| --- | --- | --- |
| 销售待办 | 销售、销售主管、管理员 | 待审核、待发货、待开票、待收款 |
| 采购待办 | 采购、采购主管、管理员 | 待审核、待到货、待入库、待收票 |
| 仓库待办 | 仓库、仓库主管、管理员 | 待入库、待出库、待领料、待盘点 |
| 生产待办 | 生产、生产主管、管理员 | 待排产、待领料、待报工、待质检 |
| 质检待办 | 质检、质检主管、管理员 | 来料待检、生产待检、不良处理 |
| 财务待办 | 财务、财务主管、管理员 | 待开票、待收款、待付款、凭证处理 |
| 系统待办 | 系统管理员、管理员 | 权限申请、异常日志、通知发布、应用配置 |

交互规则：

- 待办板块只作为首页看板展示，不作为跳转入口。
- 首页板块显示业务域总数和小分类数量，不显示单号、客户、负责人等明细。
- 小分类先用 mock 示例占位，等业务流程和状态体系做完后再按真实系统调整。
- 如果某个角色的待办为 0，仍可显示 `0`，但视觉上弱化。
- 多角色用户按业务域展示多个卡片，不把所有待办混成一个长列表。

不放：

- 常用入口。
- 营销口号。
- Logo 使用说明。
- “按当前角色过滤”这类解释性文字。

## 7. 销售模块设计

第一阶段销售模块要整体成型，而不是只做一个库存查询。

入口：

- 报价单
- 销售订单
- 销售价格记录
- 成品库存速查

销售页面结构：

1. 侧栏子菜单直接进入具体列表页：报价单、销售订单、销售价格记录、成品库存速查。
2. 面包屑显示当前具体页面，例如 `销售 / 报价单`，不重复产品名。
3. 页面主体就是当前列表，不额外放销售汇总卡片或模块切换 bar。
4. 列表页再进入详情/编辑。

销售价格记录规则：

- 由销售订单自动更新。
- 列表展示成品最新销售价格、客户、来源订单、更新时间。
- 详情展示历史单价记录。

成品库存速查：

- 搜索优先，支持成品、批次、库位。
- 显示可用库存、锁定库存、仓库/库位、批次、状态。
- 后续与销售订单、销售出库关联。

## 8. 状态体系

所有单据状态统一命名，避免同义词混用。

通用状态：

- 草稿
- 待审核
- 已审核
- 待执行
- 执行中
- 已完成
- 已关闭
- 已作废

业务状态可追加：

- 待发货
- 待入库
- 待领料
- 待报工
- 待质检
- 待开票
- 待收款

状态标签颜色：

- 普通进行中：绿色/蓝灰。
- 等待处理：琥珀。
- 异常/逾期：红色。
- 已完成：低饱和绿色。
- 作废/关闭：灰色。

## 9. 响应式断点

建议断点：

- `>= 1200px`：PC 完整布局。
- `900px - 1199px`：小桌面/横屏平板，减少右侧栏宽度。
- `720px - 899px`：平板，侧栏可收起，表格减少列。
- `< 720px`：手机，侧栏抽屉，表格转卡片。

每个页面实现前先确认手机端是否需要完整功能。不是所有 PC 功能都要塞进手机。

## 11. 阿里云部署预留

前端保持标准 Vite 静态构建：

```bash
npm run build
```

产物目录：`dist/`。

后续部署路线可选：

- ECS + Nginx：最稳，适合先上线内网/公网测试。
- Docker + Nginx：适合和后端一起编排。
- OSS + CDN：适合纯静态前端，后端 API 独立部署。

第一阶段不绑定具体部署方式，但路由要注意：如果使用 HTML5 history，需要 Nginx 配置回退到 `index.html`。
