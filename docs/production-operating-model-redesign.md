# 生产运行模型重构方案

> 日期：2026-07-19  
> 上位依据：`erp-web-prototype-blueprint.md`、`erp-web-business-fact-model.md`  
> 适用场景：3D 打印耗材的直接收卷与大盘复绕  
> 核心原则：生产批次贯穿流程，产线只承载实际设备占用，业务事件自动推动后续

## 1. 设计结论

- 生产需求回答“为什么生产、需要多少、什么时候要”。
- 生产工单冻结成品、数量、配方、工艺和交期，是计划承接对象。
- 生产批次是一次可排产、可领料、可执行、可追踪的数量单元，是用户界面的执行主线。
- 工序任务是生产批次在某类设备上的一次占用。排产安排工序任务，不把整条批次生命周期绑在产线上。
- 领料、开工、产量登记、完工、质检、包装和入库是业务记录或事件，不用一个主状态替代。
- 界面不要求普通作业逐项点击确认；只有形成数量、责任、质量、库存或异常事实的动作保留人工入口。

当前 `RB2` 释放批次和 `EC2` 生产批次可继续作为内部兼容对象，但普通页面只显示一个“生产批次”身份。释放是批次事件，不再要求使用者理解两套相邻批次编号。

## 3. 流程合同

```text
生产需求
  → 生产工单
  → 拆分生产批次
  → 生成首个工序任务
  → 确认排产
  → 仓库领料
  → 产线开工
  → 重复产量登记
  → 达量后完成设备作业并释放产线
  → 质检
  → 包装
  → 入库检
  → 仓库入库
```

- 产量登记是可重复的数量事件。累计良品和不良数量达到本批计划量时，系统自动完成设备作业并释放产线。
- 少于计划量提前结束时才需要人工“结束本批”，并强制填写短关原因；批次继续进入质量、包装和仓库流程。
- 首检、报工检和入库检由事件自动创建，生产只能查看等待结果，不代替质量判定。
- 领料和完工入库由仓库完成，生产只消费已领料和已入库凭证。
- 正常完成使用自动事件推进；只有异常、返工、报废、让步或复检进入人工处置。

## 4. 两条耗材路线

### 4.1 直接收卷

```text
挤出工序任务
  → 开机首检
  → 挤出、冷却、牵引、在线测径和小盘收卷
  → 小盘产量登记
  → 达量后自动释放挤出线
  → 成品检验
  → 包装
  → 入库检
  → 仓库入库
```

冷却、牵引、测径和收卷是“挤出生产”内部作业要求与参数记录，不拆成需要逐项确认的系统工序。

### 4.2 大盘复绕

```text
挤出工序任务
  → 开机首检
  → 大盘收卷和大盘报工
  → 大盘登记完成后释放挤出线
  → 大盘检验
  → 自动生成复绕工序任务
  → 安排复绕线并生产小盘
  → 成品检验
  → 包装
  → 入库
```

大盘和小盘继续保存一进多出谱系；复绕是新的设备占用任务，但仍属于同一生产批次主线。

## 5. 排产规则

系统按以下事实推荐产线和顺序，调度员以确认和少量调整为主：

1. 生产路线和产线能力是否匹配；
2. 材料族、直径、模具和设备要求；
3. 当前产线空闲时间；
4. 交期和加急程度；
5. 同材料、同颜色、同规格连续生产；
6. 优先浅色到深色，减少换色和清机损耗；
7. 物料齐套只阻断释放或开工，不阻止计划工单提前建立。

第一版不做复杂甘特图和全自动排程。排产页提供推荐产线、推荐班次、阻断原因和一键确认；用户只在需要时改线或改顺序。

## 6. 工作台职责

### 6.1 排产

- 主体是待排产或待释放的生产批次。
- 显示成品、数量、交期、物料、推荐产线、推荐班次和换线提示。
- 产线作为分配结果和容量资源，不作为整页唯一主体。

### 6.2 现场

- 主体是当前真正占用设备的工序任务。
- 每条产线只显示当前批次、累计产出、计划数量、开工时间、当前阻断和下一批。
- 常用人工入口只保留开工、产量登记、暂停/恢复和报告异常；正常达量自动结束，只有短关才显示“结束本批”。
- 完工后批次立即离开产线卡；待质检、待包装、待入库批次不得继续显示为产线当前任务。

### 6.3 后段

- 主体是已经结束设备占用、尚未完成入库的生产批次。
- 按待成品检、待包装、部分包装、待入库检、待仓库入库分组。
- 生产可记录包装；质量和仓库动作只提供所属模块下钻。

### 6.4 异常

- 聚合缺料、设备、工艺、质量、超损耗和返工异常。
- 异常决定是否阻断工序任务，但不覆盖批次的工艺、质量、包装和入库维度。

## 7. 人工操作最小集

| 岗位 | 正常流程人工操作 |
| --- | --- |
| 计划/调度 | 建工单、确认批次数量、确认产线和班次 |
| 仓库 | 按生产批次领料、退料、完工入库 |
| 生产操作员 | 开工、产量登记；必要时短关、暂停或报告异常 |
| 质检 | 完成系统自动生成的首检、报工检和入库检 |
| 包装 | 记录合格数量、包装数量、箱号或托盘号 |

实际耗用原则上由 `领料 - 退料` 形成；实际损耗由耗用、合格产出净重、可回收料和报废事实派生。正常操作不要求生产人员重复填写仓库已经记录的用料数量。

## 8. 状态与主动作

生产批次至少分别保存或聚合：

- 物料：未备料、备料中、齐套、缺料；
- 执行：待排产、待开工、执行中、暂停、已完工；
- 质量：未触发、待检、部分放行、不合格待处置、已放行；
- 包装：未包装、部分包装、已包装；
- 入库：未放行、待仓库、部分入库、已入库；
- 运行标记：正常、异常处理中。

页面根据当前用户责任和这些事实派生一个主动作，不允许用户维护综合主状态。

## 9. 页面与菜单建议

- 生产计划：生产需求和生产工单；
- 生产工作台：排产、现场、后段、异常；
- 生产批次：完整执行、质量、包装、入库和追溯详情；
- 异常与损耗：独立事实台账；
- 配方与工艺：规则版本维护；
- 系统动作：实施与管理员只读能力库，普通生产岗位不需要频繁进入。

## 10. 实施顺序

1. 工作台先改为排产、现场、后段、异常四区；
2. 产线卡只保留实际执行中的工序任务，报工完工后移出产线；
3. 建立后段批次队列并复用现有质检、包装和入库下钻；
4. 在界面上收敛 `RB2/EC2` 双编号，统一显示生产批次；
5. 增加重复产量登记、达量自动结束与短关事件，逐步替代“报工即完成”的旧口径；
6. 最后调整服务端对象、事件表和唯一约束，保留旧数据兼容映射。

## 11. 大盘复绕的计量与现场登记

大盘收卷和复绕成品必须使用两条并列数量链：

| 阶段 | 主数量 | 辅助事实 | 现场登记 |
| --- | --- | --- | --- |
| 大盘收卷 | 实际净重 `kg` | 大盘编号、设备、班次 | 称重后登记一个大盘批次 |
| 大盘质检 | 放行重量 `kg` | 结论、处置 | 按整盘判定，不产生成品卷数 |
| 复绕 | 实际用量 `kg` | 来源大盘、损耗 `kg` | 选择已放行大盘并记录本次投入与损耗 |
| 小盘产出 | 成品“卷” | 每卷编号、实际净重 `kg` | 系统按报工卷数生成小盘谱系 |
| 包装与入库 | 成品“卷” | 箱号、托盘号、入库凭证 | 只承接已形成的成品小盘 |

配方每单位净重只用于计划估算。大盘必须取实际称重，小盘卷数必须取实际复绕产出；系统不能把计划净重自动当成现场实际，也不能把大盘重量写进成品数量。生产批次页面同时显示两条链，但所有动作只修改所属事实。

## 12. 复绕轻量排程与设备占用

- 复绕需要设备排程，但不重新建立生产任务、生产工单、释放批次或生产批次。同一 `EC2` 生产批次下先后形成“挤出生产”和“复绕生产”两个工序任务。
- 大盘报工完成即关闭挤出工序任务并释放挤出线；等待半成品质检期间不得继续算作挤出线占用。
- 半成品质检合格后，系统按来源大盘自动生成复绕工序任务，并优先推荐、自动排入匹配的复绕线。正常情况不要求调度员再次确认；只有设备冲突、插单、故障或换线时才人工调整。
- “可开工”和“队列中”只表示已经排入队列，不表示占用设备。只有现场确认“开始复绕”后，工序任务才进入“执行中”并占用复绕线。
- 复绕开工不重复领料或首检。现场只需确认本班负责人和设备；复绕报工引用已放行大盘，分别记录实际用量 `kg`、损耗 `kg` 和成品卷数。
- 来源大盘用尽或本批成品数量达量后，复绕工序任务自动完成并释放复绕线；后续报工检、包装和入库继续沿用同一生产批次进入后段队列。

## 13. 生产批次的设备轨迹页面

- 批次详情先展示成品数量链与大盘重量链，再展示设备作业轨迹、工艺执行路线、大小盘谱系和质量承接。设备轨迹只放设备资源和实绩，工艺路线只放业务阶段与责任域，避免用一个“当前状态”解释全部流程。
- 挤出和复绕各占一行，行内固定呈现产线、计划处理、实际处理、来源大盘（复绕）、作业时间和下一步。未开始使用排入时间，执行中使用实际开始时间，完成后显示完整开始至结束区间。
- 列表把成品与设备放在一起扫描，但当前阶段、质量/入库和数量进度继续独立成列。批次顶部动作只负责进入正确工作区，真正开工仍在现场完成并记录负责人和实际设备。
- 例外调度采用渐进开放：单一兼容线只自动排入；多条兼容线且任务未开工时才显示换线或改序；执行后换线必须通过暂停、异常或短关事实闭环。

## 14. 现场开工、报工与设备释放

- 挤出开工确认负责人和实际设备，并由系统触发首检；复绕开工确认负责人和复绕设备，不重复领料和首检。开工界面显示生产批次、来源大盘和待处理重量，不显示内部工序任务编号。
- 每次报工后系统先计算本次后的剩余计划量。累计达到计划量，或复绕来源大盘本次已经用尽时，直接在报工事务中结束设备作业并释放产线，不要求操作员再点击一次“完成”。
- 未达量的普通部分报工保持设备占用；只有本次确为最后一次且现场决定提前结束时才勾选“短关”。短关与最后一笔报工一起提交，必须填写原因并冻结剩余计划量。
- 短关之后仍按实际良品生成质检、包装和入库链。剩余计划不是废弃量，也不是自动完成量，由计划人员决定补产、关闭或建立后续释放；质量处置完成后不得把已短关作业重新推回现场。
- 设备轨迹区把“达量完成、大盘用尽、短关”作为结束方式展示。批次主状态继续只作摘要，设备、质量、包装、入库和短关例外各自保存、各自派生。

## 15. 短关后的计划闭环

- 计划人员在生产批次处理“安排补产 / 接受短缺”，现场人员不通过修改计划量完成收尾。
- 安排补产沿用原工单、释放批次和生产批次，只追加设备作业。当前报工先走完质量门，再把补充作业送入现场队列；若质量不合格，先处置后再决定可补数量。
- 大盘复绕若原大盘仍有可用重量，补产继续使用该大盘；没有可用合格大盘时，系统必须明确要求先登记并放行补充大盘，不能生成无法执行的复绕任务。
- 报工质检页在判定前说明本次数量、短关剩余和判定后的自动流向；放行后直接提供“返回现场补产复绕”。现场卡、开工抽屉和当前作业都显示补产语义，但仍沿用原工单、原生产批次与来源大盘。
- 复绕补产开工只确认现场负责人，直接进入成品报工，不重复领料和首检。直接收卷补产仍按新的挤出设备作业执行开机首检，两种路线不得共用同一提示。
- 接受短缺后按实际合格量继续包装和入库，计划差异永久可追溯。报工不足、质量不良和仓库短收是三类不同事实，禁止相互冲抵。
