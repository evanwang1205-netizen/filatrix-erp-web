# 生产工艺与系统动作重构方案

> 日期：2026-07-19  
> 上位依据：`erp-web-prototype-blueprint.md`、`erp-web-business-fact-model.md`  
> 适用范围：系统动作、生产工艺、工单工艺快照、生产批次、生产工作台、生产质检  
> 当前阶段：业务模型定稿；页面改造必须在本方案之后进行

## 1. 结论

继续保留“生产工艺 + 系统动作”，但不再把生产工艺设计成按钮编排器。

- 生产工艺负责定义工艺阶段、顺序、设备、参数、作业要求、控制点和完成条件。
- 系统动作负责记录关键业务事实、自动创建下游任务或等待其他责任域返回结果。
- 工单确认或释放时冻结工艺版本快照，后续版本变化不得改写历史工单。
- 流转批次根据快照生成工序实例；现场执行读取实例，不直接读取最新模板。
- 普通作业内容只用于指导，不要求逐项点击确认。
- 只有产生责任、数量、质量、库存、批次或追溯后果的动作才设置人工入口。
- 仓库和质检拥有各自业务事实；生产只创建待办或等待结果，不代替其他模块确认完成。

## 2. 四层对象边界

### 2.1 系统动作定义

系统动作是由系统维护的固定能力，不是普通用户可以自由创建的业务资料。建议至少包含：

```ts
type SystemActionDefinition = {
  actionKey: string;
  name: string;
  ownerDomain: '生产' | '质量' | '仓库' | '系统';
  executionMode: '人工操作' | '事件自动触发' | '等待外部结果';
  commandKey?: string;
  triggerEvent?: string;
  requiredInputs: string[];
  emittedEvents: string[];
  blockingPolicy: '不阻断' | '完成前阻断' | '失败时阻断';
  repeatPolicy: '单次' | '按批次重复' | '按报工重复' | '全程可用';
  idempotencyScope: string;
  status: '启用' | '停用';
};
```

动作定义只回答“系统能做什么、由谁做、需要什么、产生什么事实”，不保存某个产品的温区、设备或作业说明。

### 2.2 生产工艺版本

生产工艺是有版本的规则模板，绑定适用产品族和产线类型。工艺节点采用有序卡片，不做任意连线的流程图编辑器。

```ts
type ProductionProcessVersion = {
  code: string;
  name: string;
  version: string;
  status: '草稿' | '启用' | '停用';
  productFamily: string;
  lineTypes: string[];
  parameters: ProcessParameterDefinition[];
  routeNodes: ProcessRouteNodeDefinition[];
  revision: number;
};

type ProcessRouteNodeDefinition = {
  nodeKey: string;
  name: string;
  sequence: number;
  nodeType: '作业阶段' | '人工关键动作' | '自动规则' | '质量门' | '外部等待';
  equipmentTypes: string[];
  workInstruction: string;
  controlPoints: string[];
  entryCondition: string;
  completionPolicy: '事件完成' | '数量达成' | '外部放行' | '人工确认';
  repeatPolicy: '不重复' | '按报工重复' | '按包装批重复';
  skipCondition?: string;
  actionBindings: string[];
  qualityPlanVersionId?: string;
  failureReturnNodeKey?: string;
};
```

第一版只支持：有序节点、条件跳过、重复执行和异常返回。不同主路线使用不同工艺版本，不引入任意分支、并行网关或 BPMN 设计器。

### 2.3 工单工艺快照

工单确认或释放时冻结完整规则，而不是只保存工艺编号：

- 工艺版本和修订号；
- 适用产线与设备要求；
- 温区和关键参数；
- 有序工艺节点；
- 节点绑定的系统动作；
- 质量计划版本；
- 跳过、重复、完成和异常返回规则；
- 冻结时间、冻结人和快照哈希。

后续模板停用或发布新版，不改变已冻结工单。

### 2.4 工序实例与动作实例

流转批次进入现场后，根据工单快照生成工序实例。规则和事实必须分开：

```ts
type ProcessNodeInstance = {
  id: string;
  executionCardId: string;
  nodeKey: string;
  sequence: number;
  status: '未进入' | '可执行' | '执行中' | '等待外部' | '已完成' | '已跳过' | '异常阻断';
  startedAt?: string;
  completedAt?: string;
  blockingReason?: string;
  revision: number;
};

type ProcessActionInstance = {
  id: string;
  nodeInstanceId: string;
  actionKey: string;
  status: '待触发' | '可操作' | '处理中' | '等待结果' | '已完成' | '失败' | '已取消';
  sourceEventId?: string;
  resultDocument?: string;
  actor?: string;
  occurredAt?: string;
  idempotencyKey: string;
};
```

同一工艺节点可以长期处于执行中，并发生多次报工、检验或包装动作；禁止用“节点已完成”覆盖这些明细事实。

## 3. 系统动作首版能力库

| 动作 | 责任域 | 方式 | 触发/入口 | 结果 | 是否阻断 |
| --- | --- | --- | --- | --- | --- |
| 创建生产领料待办 | 系统/仓库 | 自动 | 释放批次成功 | 生产领料待办 | 发料前阻断开工 |
| 记录物料准备 | 生产 | 人工、按需 | 工艺要求烘干或预处理 | 设备、温度、时间和物料批次记录 | 工艺要求时阻断 |
| 开始生产 | 生产 | 人工 | 已领料且产线、设备、班次明确 | 开工事件 | 阻断首检前生产报工 |
| 创建开机首检 | 系统/质量 | 自动 | 开工成功 | 开机首检任务 | 首检放行前阻断报工 |
| 半成品报工 | 生产 | 人工、可重复 | 大盘完成或阶段报工 | 半成品报工和批次事实 | 当前报工等待质量判定 |
| 成品报工 | 生产 | 人工、可重复 | 小盘完成或阶段报工 | 成品报工和数量事实 | 当前报工等待质量判定 |
| 创建报工检验 | 系统/质量 | 自动 | 报工提交且质量计划命中 | 生产质检任务 | 该承接数量放行前阻断后续消费 |
| 记录包装 | 生产 | 人工、可重复 | 合格成品可包装 | 盘号、箱号、标签和包装数量 | 未包装数量不得入库检 |
| 创建入库检验 | 系统/质量 | 自动 | 包装记录完成且规则要求 | 入库检验任务 | 放行前阻断仓库入库 |
| 创建完工入库待办 | 系统/仓库 | 自动 | 入库检放行或免检 | 完工入库待办 | 仓库过账前不增加库存 |

暂停、恢复、异常上报和交接班是流转批次全程可用的上下文动作，不重复编排到每一条工艺路线中。

## 4. 质量门设计

质检不是生产人员点击完成的普通工序。工艺节点引用已启用的质量计划版本，并声明触发策略：

- 开机后首件必检；
- 每次报工检；
- 每个生产批次检；
- 按时间或数量频次抽检；
- 包装后入库检；
- 免检。

生产域自动创建质检任务后，工序实例进入“等待外部”；质量域保存标准快照、判定和处置，产生放行或阻断凭证。生产只消费结果，不直接修改质检结论。

不合格时不能简单进入下一工序。根据处置生成返工、复检、让步、报废或隔离事实，并按工艺快照中的 `failureReturnNodeKey` 返回指定阶段。

## 5. 两条耗材工艺路线

### 5.1 直接收卷路线

适用于拉丝后直接形成小盘成品：

1. 物料准备：等待仓库发料；需要时记录烘干参数。
2. 开机：记录产线、设备、班次、操作人和原料批次。
3. 开机首检：自动创建质量任务，放行后进入连续生产。
4. 拉丝与直接收卷：展示温区、速度、测径和收卷要求，不要求逐项确认。
5. 成品报工：按小盘或生产批重复，可多次提交。
6. 报工检验：按质量计划自动触发，只放行对应承接数量。
7. 包装：按箱或包装批重复记录盘号、箱号和标签。
8. 入库检验：按规则自动触发。
9. 完工入库：系统创建仓库待办，仓库过账后形成可用库存。

### 5.2 大盘复绕路线

适用于先形成大盘半成品、再复绕为小盘：

1. 物料准备。
2. 开机与开机首检。
3. 拉丝和大盘收卷：持续作业，不逐步点击。
4. 半成品报工：每个大盘独立报工，可重复。
5. 半成品检验：自动触发；合格大盘才可进入复绕。
6. 复绕和小盘收卷：引用来源大盘，保留一进多出谱系。
7. 成品报工：按小盘或生产批重复。
8. 成品检验、包装和入库检验。
9. 完工入库。

直接收卷与大盘复绕首版使用两张独立工艺模板，不在同一模板中配置复杂条件分支。

## 6. 状态分维

任何页面都不得用一个主状态承担全部生产含义。至少分开：

| 维度 | 示例 |
| --- | --- |
| 工艺阶段 | 物料准备、开机、拉丝、复绕、包装、待入库 |
| 当前动作 | 可开工、可报工、等待检验、可包装 |
| 物料状态 | 待领料、部分领料、已领料、缺料 |
| 质量状态 | 未触发、待检、部分放行、不合格待处置、已放行 |
| 包装状态 | 未包装、部分包装、已包装 |
| 入库状态 | 未放行、待仓库入库、部分入库、已入库 |
| 运行标记 | 正常、暂停、异常处理中 |

列表主提示和工作台主动作由上述事实派生，中文提示不参与业务判断，也不允许用户直接维护。

## 7. 页面职责

### 7.1 系统动作

- 定位为管理员/实施人员查看的只读能力库。
- 普通生产人员不显示菜单入口。
- 不提供自由新建、复制、编辑、停用或按钮名称配置。
- 列表显示动作、责任域、执行方式、触发来源、结果和阻断规则。
- 详情显示输入、输出、幂等范围、异常规则和引用工艺，不展示交易单据式流程节点。

### 7.2 生产工艺

- 列表关注工艺编号、名称、路线类型、适用范围、版本、工序阶段和状态。
- 新建/编辑页使用“工艺基础、关键参数、工艺路线”三部分。
- 工艺路线使用有序卡片；卡片显示作业要求、设备、控制点、完成条件和受控动作绑定。
- 质检位置显示质量计划和触发策略，不允许自由填写“质检标准”文本。
- 系统动作只从固定能力库选择；普通作业节点可以不绑定动作。

### 7.3 工单、批次与工作台

- 工单详情显示冻结后的工艺快照，不从最新工艺模板反查历史内容。
- 流转批次显示实际工序实例、动作实例、报工、检验、包装和入库事实。
- 工作台只给当前责任人一个明确主动作；等待仓库、等待质检和异常阻断显示原因及下钻入口。
- 暂停、恢复、异常上报和交接班作为全程动作独立呈现。

## 8. 实施顺序

1. 更新生产类型和假数据：拆分动作定义、工艺节点定义、工单快照、工序实例和动作实例。
2. 重做系统动作列表和详情为只读能力库。
3. 重做生产工艺列表、新建和详情，先落地两条独立耗材路线。
4. 工单保存完整工艺快照，流转批次按快照生成实例。
5. 工作台改为事件驱动的“当前动作 + 等待结果 + 全程动作”。
6. 质检、仓库继续拥有各自事实，只通过任务、凭证和事件与生产联动。
7. 用直接收卷、大盘复绕、首检失败、重复报工、部分合格、暂停恢复和异常返工场景回归。

## 9. 本阶段不做

- 不引入 BPMN、任意连线、并行网关或脚本表达式。
- 不允许用户自由创建系统动作或配置任意接口。
- 不把温区、作业内容和质量标准塞进系统动作定义。
- 不让生产页面直接完成仓库过账或质检判定。
- 不用一个主状态代替工序、物料、质量、包装、入库和异常事实。

## 10. 当前落地进度（2026-07-19）

- 已完成系统动作能力库的数据拆分、列表与只读详情，动作定义不再与工艺阶段一一重复。
- 已完成生产工艺列表、新建、编辑和详情的第一版重构；工艺路线按阶段类型、执行规则、作业要求、完成条件和异常处理呈现。
- 已接入生产工艺草稿保存、启用、停用、版本唯一性、乐观锁、审计记录和路线校验；系统会校验直接收卷与大盘复绕的必要阶段，不接受任意按钮编排。
- 已用隔离临时数据完成“新建草稿 -> 启用版本”的端到端接口验证，未污染当前演示数据。
- 已完成工单服务端可信工艺快照：提交时校验启用版本并冻结模板、阶段、来源修订、时间和哈希，不再要求客户端提供完整可信快照。
- 已完成流转批次阶段/动作实例：生产领料过账生成 `EC2` 时，从工单快照实例化直接收卷或大盘复绕路线，并按开工、质检、报工、包装和入库事件刷新当前阶段、动作状态和来源凭证。
- 生产工作台已把固定“十步提示”改为优先读取当前批次实例；批次详情新增“工艺执行路线”，同时展示阶段、责任域、固定系统动作、业务凭证、等待对象和下一步。
- 隔离数据端到端测试已覆盖 `MO2 → RB2 → WM2 → EC2 → 首检 → 报工检 → 包装 → 入库检 → WPR2`，验证批次创建时有 8 个直接收卷阶段、首检后推进当前阶段、正式入库后全部阶段关闭。
- 下一阶段继续补强事件账本和大盘复绕专用执行事实：把读时同步收敛为显式事件驱动持久化，并细化大盘一进多出谱系、半成品报工与复绕工作台操作。
