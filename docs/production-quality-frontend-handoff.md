## 目标

先只调整生产、质检模块前端，但判断标准继续以六模块一致性为准。生产、质检不能只做到能用，需要对照已经优化过的销售、采购、仓库、基础资料页面，逐页检查每一处可见内容、字段、按钮、菜单、弹层、hover、focus、disabled、点击前后状态、toast、日志、附件、右侧摘要和流程表达，修到系统口径一致。

当前六模块总目标仍未完成，本专项只是把下一轮工作范围收缩到生产、质检。

## 参考基准

- 销售订单详情：顶部动作顺序、更多菜单、日志入口、下一步条、右侧流程节点和摘要。
- 销售报价、采购申请、物料采购详情：转单、确认、变更、草稿删除、风险动作确认、禁用原因和 title 说明。
- 仓库采购入库、销售出库、其他仓库作业详情：库存/流水后果说明、主动作反馈、只读状态和右侧摘要。
- 基础资料物料、客户、供应商、仓库维护页：规则/主数据页面，不套用业务单据流程语义。

## 必查页面

生产：

- 列表：生产任务、生产工单、流转批次、损耗台账、物料配方、工艺模板、工序模板、异常闭环。
- 详情/规则页：生产任务、生产工单、流转批次、物料配方、工艺模板、工序模板、异常闭环。
- 新建/编辑/变更页：除损耗台账外，上述页面对应入口。
- 生产工作台现场执行已开始改为“左侧产线 / 右侧当前工序、操作、推进状态、相关信息”，仍需逐线浏览器复核。
- 损耗台账是纯列表记录类页面，只承接其他流程产生的损耗记录；不显示新建、详情、变更、确认、关闭、更多、日志、附件上传等业务操作按钮，行和状态不跳详情。

质检：

- 列表：来料质检、生产质检、质量巡检、质检标准、不良记录。
- 详情/规则页：来料质检、生产质检、质量巡检、质检标准、不良记录。
- 新建/编辑/变更页：上述所有页面对应入口。
- 质量巡检是现场主动巡检、随机抽查和整改复查记录，可关联工单/批次/产线，但不替代生产质检固定节点。
- 质检标准是规则/主数据类页面，不能错误套用业务单据的流程节点、下一步、主动作和日志结构。

## 检查要求

列表页：

- 标题区、模块小标题、主按钮短名、按钮 title、搜索、排序、筛选、导出、弹层、空输入、点击反馈。
- 表头、列宽、固定状态列、横向滚动、分页、计数、空态。
- 行 hover/focus、状态列 hover/focus、整行点击、状态列点击、移动端卡片点击。
- 状态列必须表达“状态 + 下一步/维护动作”，不能让下一步看起来像第二个状态。
- 列表字段只承担查找和判断，不堆详情字段，不重复右侧状态列信息。

详情页：

- 顶部动作顺序固定为“悬浮 / 打印 / PDF / 日志 / 更多 / 主动作”。
- 低频或风险动作进入“更多”，风险动作需要确认，取消后不能继续变更状态。
- 草稿或主数据维护用“编辑”，已流转业务单据用“变更”。
- 主动作短名、title、禁用原因、点击成功/失败 toast、状态变化、右侧下一步必须一致。
- “下一步”条右侧显示可执行动作或维护动作，不重复当前状态。
- 业务单据右侧第一块叫“流程节点”，规则/主数据页面不能叫流程节点。
- 右侧摘要只放真实摘要、关联单据、库存/质量/风险/附件，不重复日志列表。
- 日志统一由顶部“日志”按钮打开。
- 附件区上传、只读、禁用、title、aria-disabled 和文件输入禁用状态必须一致。

新建/编辑/变更页：

- 不显示尚未形成单据的业务流程节点和顶部下一步条。
- 必填标签、校验 toast、字段高亮、焦点落点、保存/提交前后状态和按钮禁用必须一致。
- 所有可编辑字段必须真实写回草稿；只读字段必须明确只读，不能伪装成可编辑。
- 明细新增、删除、禁用、只读、空明细、字段模板、专属业务字段必须符合生产或质检自身场景。
- 取消、保存草稿、保存、提交、确认、变更提交的 title 和点击后反馈必须清楚。

共享控件：

- 按钮、图标按钮、链接、菜单项、分页、标签、chip、分段按钮、上传按钮、弹层关闭按钮均需具备 title 或 aria-label。
- 更多菜单需要 role、aria-haspopup、aria-expanded、aria-controls、菜单项 title、禁用原因和风险项确认。
- 筛选弹层、引用选择器、参考抽屉、异常处理弹层、条款或模板弹层的输入框、select、textarea、checkbox 都要有字段级说明。
- Hover、focus、disabled、loading、empty、error、success、toast、confirm 必须用浏览器实际点到。

## 已有基础

- 生产/质检详情顶部动作区已按销售/采购方式补过“悬浮 / 打印 / PDF / 日志 / 更多 / 主动作”。
- 右侧重复日志块已清理，日志统一由顶部“日志”按钮打开。
- 生产/质检流程节点、下一步、状态列、列表 hover、按钮短名、附件上传、错误态 toast、必填校验、共享弹层字段说明已做过多轮补强。
- 这些只能作为基础，不等于最终完成；新对话仍需逐页用浏览器证明。

## 建议执行顺序

1. 先打开销售订单详情、生产任务详情、生产质检详情并排对照，优先检查流程节点、下一步、右侧摘要、顶部按钮和更多菜单。
2. 再扫生产 8 个列表和质检 5 个列表，确认列表主按钮短名、状态列、行高亮、分页、工具栏、空态一致。
3. 再扫生产和质检所有详情/规则页，区分业务单据和规则/主数据页面。
4. 再扫所有新建/编辑/变更页，重点检查字段真实填选、必填、校验、toast、焦点、保存/提交后状态。
5. 每修一类问题都补入 `filatrix-erp-web/scripts/audit-ui-consistency.mjs` 或现有烟测，避免只修一个页面。
6. 最后运行 `npm.cmd run audit:ui`、`npm.cmd run smoke:frontend`、`npm.cmd run build`，并把浏览器复核结果写回优化方案。

## 2026-07-14 可验收链路

- 生产任务可进入备料申请和计划工单，已有工单可直接下钻；物料表按预计用量、可用库存、缺口、已申请、待检、锁定和备料状态表达。
- 生产工单可查看配方/工艺快照及关联流转批次；流转批次可进入生产质检或完工入库，工作台沿用同一批次和状态语言。
- 生产质检使用流转批次作为来源，来料质检使用采购收货单作为来源，两者不再共用错误回写对象。
- 来料质检合格或让步放行后，来源收货单从待质检推进到待入库；不合格继续停留在质量处置，不直接进入可用库存。
- 完工入库新建页可由流转批次/工单带入来源、成品、数量和单位，避免重复手填。

仍待底层完成：工单释放时的原子预留、现场发料锁定、质检部分数量处置、库存台账过账、重复提交幂等和跨模块审计日志。前端当前只证明对象边界、字段和操作入口。
